# Часть I. Начало работы

## Введение

Amane — библиотека на Rust для создания собственной оболочки рабочего стола Wayland: баров, панелей, лаунчеров, всплывающих уведомлений и экранов блокировки. Вся оболочка пишется как одна программа на Rust. Она подключается напрямую к композитору и рисует на GPU, без браузерного движка, QML и GTK.

Вот полностью готовый бар:

```rust
use amane::{App, Color, Full, Layer, LayerWindow, Parent, Rectangle, Text, Vertical};

fn main() {
    App::new().window(view).run();
}

fn view() -> LayerWindow {
    LayerWindow::new()
        .width(Full)
        .height(30.0)
        .anchor_vertical(Vertical::Top)
        .layer(Layer::Top)
        .child(
            Rectangle::new()
                .width(Parent)
                .height(Parent)
                .fill(Color::BLUE)
                .child(Text::new("Amane bar").size(20.0).color(Color::WHITE)),
        )
}
```

Это синяя полоса высотой 30 пикселей во всю ширину экрана с белым текстом.

### Что нужно

- Wayland-композитор с поддержкой **wlr-layer-shell**: niri, Hyprland, Sway, river и другие. GNOME эту возможность не поддерживает.
- GPU с работающим драйвером Vulkan.
- Немного Rust. Глубоко знать язык не обязательно: достаточно понимать функцию, структуру и замыкание вида `|x| ...`. Там, где Amane использует что-то менее очевидное, это объясняется по ходу текста.

> **Уточнение.** Для сборки нужен не только Rust, но и C-компилятор, `pkg-config`, заголовки FreeType и expat. Подробности — в разделе «Установка».

### Как устроена книга

- **Начало работы** — установка и первый бар.
- **Основные понятия** — представления, окна, компоновка, состояние, ввод и анимация. Эти главы лучше читать по порядку.
- **Виджеты** — подробно о каждом строительном блоке.
- **Дополнительные окна** — несколько мониторов, обычные окна и экран блокировки.
- **Встроенные сервисы** — системные данные, которые Amane читает сам: батарея, звук, сеть, медиаплееры, уведомления и другое.
- **Связь с системой** — запуск команд, наблюдение за файлами, IPC и D-Bus.

Каждый пример начинается со строки `use`, чтобы было видно, откуда взято имя. Если не сказано иное, все имена импортируются из `amane`.

Если интересует внутреннее устройство библиотеки, в репозитории есть `ARCHITECTURE.md`.

## Шпаргалка

Все основные builder-методы и функции на одной странице. Имена взяты из `amane`; чтобы подключить всё сразу:

```rust
use amane::*;
```

### `App`

| Код | Что делает |
|---|---|
| `App::new()` | начинает сборку оболочки |
| `.window(view)` | добавляет слойное окно; `fn() -> LayerWindow` |
| `.window_per_monitor(view)` | добавляет слойное окно на каждый монитор; `fn(&Monitor) -> LayerWindow` |
| `.normal_window("name", view)` | добавляет обычное окно приложения; `fn() -> Window` |
| `.lock(view)` | задаёт экран блокировки; `fn(&Monitor) -> LayerWindow` |
| `.ipc("name", handler)` | обрабатывает `amane ipc call name`; `fn(&[String]) -> String` |
| `.without_ipc()` | запускает без IPC-сокета, рядом с другой Amane-оболочкой |
| `.font("Inter")` | задаёт семейство шрифта по умолчанию |
| `.scale_factor(1.4)` | масштабирует все окна и виджеты; по умолчанию `1.0` |
| `.run()` | запускает цикл событий |

> **Уточнение.** `.window`, `.window_per_monitor`, `.normal_window`, `.lock` и `.ipc` принимают указатели на функции (`fn`), а не замыкания с захватом. Если нужно состояние, храните его в сервисе.

## Установка

Amane поставляется одной командой `amane`. Внутри неё лежит полная копия библиотеки. Команда собирает оболочку из вашей папки конфигурации, поэтому создавать Cargo-проект вручную не нужно.

### NixOS

Репозиторий является flake. Пакет оборачивает `amane` со всем, что нужно для сборки: `cargo`, `rustc`, `pkg-config` и системные библиотеки.

Попробовать без установки:

```sh
nix run github:MystiaFin/amane -- new
```

Установить для пользователя:

```sh
nix profile install github:MystiaFin/amane
```

Установить системно — добавьте flake во входы конфигурации:

```nix
{
  inputs = {
    nixpkgs.url = "github:NixOS/nixpkgs/nixos-unstable";
    amane = {
      url = "github:MystiaFin/amane";
      inputs.nixpkgs.follows = "nixpkgs";
    };
  };

  outputs = { nixpkgs, amane, ... }: {
    nixosConfigurations.your-host = nixpkgs.lib.nixosSystem {
      system = "x86_64-linux";
      modules = [
        ./configuration.nix
        {
          environment.systemPackages = [ amane.packages.x86_64-linux.default ];
        }
      ];
    };
  };
}
```

Замените `your-host` на имя хоста и пересоберите систему.

Строка `follows` заставляет Amane использовать `nixpkgs` вашей системы, чтобы совпадала glibc с графическим драйвером. Без неё оболочка может не найти GPU.

| expat | `libexpat1-dev` | `expat` |
| Vulkan loader | `libvulkan1` | `vulkan-icd-loader` |
| PulseAudio client | `libpulse-dev` | `libpulse` |
| PAM | `libpam0g-dev` | `pam` |
| C-компилятор | `build-essential` | `gcc` |

Также нужен `pkg-config` (`pkgconf` в Arch). Готовый набор ставит `install.sh` из репозитория.

Сборка и установка команды:

```sh
git clone https://github.com/MystiaFin/amane
cd amane
cargo install --path cli
```

`cargo install` кладёт `amane` в `~/.cargo/bin`. Убедитесь, что эта папка есть в `PATH`.

Команда `amane` запускает `cargo` при каждой сборке вашей оболочки, поэтому toolchain Rust должен оставаться установленным.

> **Исправление.** Оригинальная таблица зависимостей не упоминает C-компилятор, FreeType и expat. Без них сборка завершится ошибкой линковки или `pkg-config`.

### Обновление

Библиотека копируется внутрь команды `amane` при её сборке. Чтобы получить новую версию, обновите саму команду:

- NixOS: `nix profile upgrade amane` или обновите flake-вход и пересоберите систему.
- Другие дистрибутивы: `git pull` в клоне, затем снова `cargo install --path cli`.

Следующий `amane compile` или `amane dev` пересоберёт оболочку с новой библиотекой.

## Первая оболочка

Эта глава ставит бар на экран, а затем меняет его на лету.

### 1. Создайте конфигурацию

```sh
amane new
```

Команда спросит, куда положить оболочку. Нажмите Enter, чтобы использовать `~/.config/amane` (или `$XDG_CONFIG_HOME/amane`). В этой главе предполагается путь по умолчанию. Будет создан `src/main.rs` с небольшим баром. Если файл уже существует, `new` остановится и ничего не перезапишет.

> **Уточнение.** Если задана переменная `AMANE_CONFIG`, вопрос не задаётся: оболочка создаётся по указанному в ней пути. Сохранённый `amane target` на выбор папки для `amane new` без аргументов не влияет.

### 2. Запустите режим разработки

```sh
amane dev
```

Первая сборка занимает несколько минут: компилируются Amane и все зависимости. После этого бар появится вверху экрана.

Оставьте `amane dev` запущенным. При каждом сохранении `main.rs` оболочка пересобирается и перезапускается. Если сборка не удалась, старый бар остаётся на экране, пока вы исправляете ошибку.

Одновременно может работать только одна Amane-оболочка. Если оболочка уже запущена через `amane run`, остановите её перед `amane dev`.

### 3. Прочитайте файл

Откройте `~/.config/amane/src/main.rs`:

```rust
use amane::{App, Color, Full, Layer, LayerWindow, Parent, Rectangle, Text, Vertical};

fn main() {
    App::new().window(view).run();
}

fn view() -> LayerWindow {
    LayerWindow::new()
        .width(Full)
        .height(30.0)
        .anchor_vertical(Vertical::Top)
        .layer(Layer::Top)
        .child(
            Rectangle::new()
                .width(Parent)
                .height(Parent)
                .fill(Color::BLUE)
                .child(Text::new("hello from amane").size(20.0).color(Color::WHITE)),
        )
}
```

Сверху вниз:

- `use amane::{...}` подключает все имена, которые использует файл.
- `main` создаёт `App`, передаёт ему одно окно и запускает. `run()` не возвращается, пока оболочка открыта.
- `.window(view)` передаёт саму функцию `view`, не вызывая её. Amane вызывает её всякий раз, когда окно нужно перерисовать.
- `view` описывает окно:
  - `.width(Full)` — во всю ширину монитора;
  - `.height(30.0)` — высота 30 пикселей;
  - `.anchor_vertical(Vertical::Top)` — прикрепить к верхнему краю;
  - `.layer(Layer::Top)` — выше обычных окон.
- Внутри окна — `Rectangle`, который заполняет его (`Parent` означает «столько, сколько даёт родитель») и закрашен синим.
- Внутри прямоугольника — `Text`.

### 4. Измените бар

Не останавливая `amane dev`, поменяйте цвет и текст:

```rust
use amane::{App, Color, Full, Layer, LayerWindow, Parent, Rectangle, Text, Vertical};

fn main() {
    App::new().window(view).run();
}

fn view() -> LayerWindow {
    LayerWindow::new()
        .width(Full)
        .height(30.0)
        .anchor_vertical(Vertical::Top)
        .layer(Layer::Top)
        .child(
            Rectangle::new()
                .width(Parent)
                .height(Parent)
                .fill("#1e1e2e")
                .child(Text::new("my shell").size(16.0).color(Color::from("#cdd6f4"))),
        )
}
```

Сохраните файл — бар перезапустится с новым видом.

`.fill` принимает hex-строку напрямую. `.color` у `Text` принимает `Color`, поэтому hex нужно обернуть в `Color::from`.

### 5. Запустите по-настоящему

`amane dev` останавливает оболочку, когда вы завершаете команду. Когда результат устраивает, соберите её один раз:

```sh
amane compile
```

Затем запустите:

```sh
amane run
```

`amane run` запускает оболочку в фоне, поэтому терминал можно закрыть. Команда никогда не собирает: она запускает только то, что сохранил `amane compile`. После правок используйте `amane compile --restart`, чтобы собрать и сразу подменить работающую оболочку.

Чтобы оболочка запускалась при входе, вызовите `amane run` из конфигурации автозапуска композитора. Для niri:

```kdl
spawn-at-startup "amane" "run"
```

## Команда `amane`

| Команда | Что делает |
|---|---|
| `amane new` | Спрашивает, куда положить оболочку (Enter — `~/.config/amane`), затем создаёт там `src/main.rs` из шаблона и `Cargo.toml` для редактора. Никогда не перезаписывает существующий файл оболочки. |
| `amane new <folder>` | То же в указанной папке, без вопроса. Amane запоминает папку, как `amane target`. |
| `amane new [folder] --example` | Создаёт полноценный пример бара из нескольких файлов, с кнопками рабочих столов для каждого монитора. Никогда не перезаписывает существующие файлы. |
| `amane target <folder>` | Указывает Amane на существующую оболочку, например после переноса или клонирования dotfiles. В папке должен быть `src/main.rs`. |
| `amane target` | Печатает папку, из которой Amane собирает оболочку. |
| `amane dev` | Собирает оболочку, запускает её и пересобирает с перезапуском при каждом сохранении. |
| `amane compile` | Собирает оболочку и сохраняет её как `~/.cache/amane/amane-shell`, не запуская. |
| `amane compile --restart` | То же, затем перезапускает работающую оболочку новой сборкой, как `amane restart`. Если сборка не удалась, ничего не перезапускает. |
| `amane run` | Запускает сохранённую `amane compile` оболочку в фоне и возвращает терминал, поэтому закрытие терминала её не остановит. Никогда не собирает. Завершается с ошибкой, если оболочка уже запущена. |
| `amane restart` | Останавливает оболочку, запущенную `amane run`, и запускает сохранённую `amane compile`. Если ничего не было запущено, всё равно запускает. Оболочку из `amane dev` не трогает. |
| `amane clean` | Удаляет результаты сборки в `~/.cache/amane/project/`. Скомпилированную оболочку оставляет, поэтому `amane run` продолжает работать. Спрашивает подтверждение. |
| `amane clean --yes` | То же без вопроса. |
| `amane ipc call <name> [arguments...]` | Вызывает обработчик в работающей оболочке. |

> **Уточнение.** `amane startup [--example]` — устаревший псевдоним `amane new`. Он пока работает, печатает предупреждение и не принимает папку аргументом. В книге эта команда не упоминалась.

### Где что лежит

- **Ваша оболочка:** `~/.config/amane/src/` или папка, указанная в `amane new` / `amane target`. Точка входа — `main.rs`. Рядом можно добавлять другие файлы и подключать их через `mod`, как в обычной программе на Rust.
- **Какая папка используется:** `amane target` печатает путь. Папка, отличная от стандартной, сохраняется в `~/.local/state/amane/config-path` — отдельно для каждой машины, чтобы не попадать в dotfiles. На новой машине выполните `amane target` заново.
- **Поддержка редактора:** `Cargo.toml` рядом с `src/`. `amane new` создаёт его, а каждая сборка обновляет, чтобы rust-analyzer находил Amane и подсказывал типы. Не редактируйте этот файл: в нём пути только для текущей машины. Если храните оболочку в git, добавьте в `.gitignore` `Cargo.toml`, `Cargo.lock` и `target/`.
- **Файлы сборки:** `~/.cache/amane/`.
  - `library/` — распакованная копия Amane из команды;
  - `project/` — сгенерированный Cargo-проект вокруг вашего `main.rs`;
  - `project/target/` — результаты сборки;
  - `amane-shell` — сохранённая `amane compile` оболочка, которую запускает `amane run`.

Пути следуют переменным `XDG_CONFIG_HOME`, `XDG_STATE_HOME` и `XDG_CACHE_HOME`, если они заданы.

Ничего в кэше редактировать не нужно. Удалять его безопасно: следующая сборка создаст всё заново.

`project/` — самый большой каталог, часто около 1 ГБ. Он нужен только для быстрых пересборок, оболочка его не читает. `amane clean` удаляет его и спрашивает подтверждение, потому что следующая сборка займёт несколько минут. Собрать и сразу почистить без вопроса:

```sh
amane compile && amane clean --yes
```

> **Уточнение.** `amane clean` удаляет только `project/`, а не `library/` и не `amane-shell`. Поэтому `amane run` после очистки продолжает работать.

### Разделение оболочки на файлы

`main.rs` может подключать другие файлы обычным для Rust способом:

```text
~/.config/amane/src/
├── main.rs
├── bar.rs
└── clock.rs
```

```rust
// main.rs
mod bar;
mod clock;

use amane::App;

fn main() {
    App::new().window(bar::view).run();
}
```

`amane dev` следит за всей папкой `src/`, поэтому сохранение любого из этих файлов запускает пересборку.

### Как собирается оболочка

`amane dev` и `amane compile` используют одну и ту же сборку, поэтому результаты хранятся на диске один раз.

| Что | Оптимизация |
|---|---|
| Ваш код | нет, чтобы сохранение пересобиралось за секунды |
| Amane и зависимости | да |

Amane всегда оптимизирован: неоптимизированная отрисовка слишком медленная для плавной анимации. Ваш код только описывает оболочку, а тяжёлую работу делает библиотека, поэтому неоптимизированный пользовательский код не замедляет готовую оболочку.

> **Уточнение.** В справке CLI результат `amane compile` назван «optimised shell», но фактически используется `cargo build` без `--release`. Ваш код собирается в debug-профиле; оптимизированы только зависимости.

### Зависимости

`Cargo.toml` вашей оболочки генерируется при каждой сборке и зависит только от `amane`. Добавить другие crates в оболочку пока нельзя.

Большая часть нужного уже есть в библиотеке:

- системные данные через встроенные сервисы;
- запуск команд и чтение вывода;
- наблюдение за файлами, D-Bus и IPC.

Для всего остального, например текущего времени, запускайте команду через `amane::output` (`date +%H:%M`).

# Часть II. Основные понятия

## Представления

Бар показывает данные, которые меняются: время, заряд батареи, громкость. Большинство UI-библиотек создаёт виджеты один раз, а затем вы пишете код, обновляющий каждый виджет при изменении данных. Amane работает иначе. **Представление** (`view`) — это функция, которая описывает, что показывает окно, и Amane вызывает её заново каждый раз, когда это должно измениться. Отдельный код обновления писать не нужно.

В этой главе объясняется, когда вызывается `view` и какое правило из этого следует.

### Представление с живыми данными

```rust
use amane::{App, Battery, Full, LayerWindow, Service, Text};

fn main() {
    App::new().window(view).run();
}

fn view() -> LayerWindow {
    let battery = Battery::read();

    LayerWindow::new()
        .width(Full)
        .height(30.0)
        .child(Text::new(format!("battery {}%", battery.percent())))
}
```

Когда батарея переходит с 80% на 79%, текст меняется сам.

### Когда выполняется `view`

`view` вызывается заново каждый раз, когда окну нужно измениться:

1. Amane вызывает `view`.
2. `view` читает батарею (80%) и строит новое окно с `Text`, который говорит «80%».
3. Amane рисует результат и выбрасывает виджеты.
4. Батарея опускается до 79%.
5. Amane снова вызывает `view`. Он читает 79% и строит новый `Text` с «79%».

Первая отрисовка и каждое обновление проходят через одну и ту же функцию, поэтому экран всегда соответствует данным.

Amane также знает, **какие** окна нужно вызвать снова. `Battery::read()` записывает, что это представление читало батарею. При изменении батареи перерисовываются только окна, чьи представления её читали. Окно, которое никогда не читает батарею, не затрагивается. Подробнее — в главе «Состояние и сервисы».

### Состояние вне представления

Виджеты выбрасываются после каждого кадра, поэтому:

> **Ничто, сохранённое в виджете, не переживает следующий кадр.**

Всё, что должно сохраняться — счётчик, открыто ли меню, текст, введённый пользователем — должно жить вне `view`. Amane даёт три места:

- **сервис** для вашего собственного состояния;
- встроенное хранилище по имени, которое используют `ScrollArea` и `TextInput`, чтобы сохранять позицию прокрутки и текст между кадрами. Каждому даётся имя: `ScrollArea::new("apps", ...)`;
- `static`, которым управляете вы сами, например `thread_local!` или `Mutex`. Окно, в котором произошёл клик или ввод, всегда перерисовывается после события, поэтому `static`, изменённый его собственным обработчиком ввода, будет виден. Но `static`, изменённый в другом месте — из потока или обработчика другого окна — ничего не перерисует. Сервис перерисовывает каждое окно, которое его читает, независимо от того, откуда пришло изменение.

### Что представление должно и не должно делать

`view` выполняется часто, иногда 60 раз в секунду во время анимации, в том же потоке, который рисует все окна. Поэтому представление должно:

- **читать** данные (`SomeService::read()`) и **строить** виджеты;
- **не ждать**: никаких запусков команд, чтения файлов, сетевых вызовов и `sleep`.

Медленная работа идёт в отдельном потоке сервиса. Представление лишь читает результат.

### Разделение представления на функции

`App::window` принимает `fn() -> LayerWindow` — функцию без аргументов, возвращающую окно. Это не может быть замыкание, захватывающее переменные. Сделано это намеренно: раз представление ничего не захватывает, всё, что оно показывает, должно приходить из места, за которым Amane может наблюдать.

Представление можно свободно разбивать на вспомогательные функции:

```rust
use amane::{App, Color, Full, LayerWindow, Parent, Rectangle, Row, Text, children};

fn main() {
    App::new().window(view).run();
}

fn view() -> LayerWindow {
    LayerWindow::new()
        .width(Full)
        .height(30.0)
        .child(Row::new(children![label("left"), label("right")]))
}

fn label(content: &str) -> Rectangle {
    Rectangle::new()
        .width(Parent)
        .height(Parent)
        .fill(Color::BLACK)
        .child(Text::new(content).color(Color::WHITE))
}
```

Вспомогательные функции могут принимать аргументы и возвращать любой тип виджета. Фиксированная сигнатура только у верхнеуровневого `view`.

### Термины

- **Представление (view):** функция, которая строит виджеты окна из текущих данных.
- **Кадр (frame):** один запуск представления плюс отрисовка результата.
- **Immediate mode:** стиль UI, при котором виджеты строятся заново каждый кадр, а не хранятся и обновляются.

## Слойные окна

`LayerWindow` — окно, которое является частью рабочего стола, а не приложением: бар, док, всплывающее окно, обои. Обычное окно приложения композитор размещает сам, и другие окна могут его перекрывать. Слойное окно прикрепляется к краю экрана, лежит на выбранном слое и может резервировать место, чтобы другие окна его не перекрывали.

В этой главе рассматриваются все эти настройки.

### Бар

```rust
use amane::{App, Color, Full, Layer, LayerWindow, Parent, Rectangle, Vertical, Zone};

fn main() {
    App::new().window(view).run();
}

fn view() -> LayerWindow {
    LayerWindow::new()
        .width(Full)
        .height(32.0)
        .anchor_vertical(Vertical::Top)
        .layer(Layer::Top)
        .space(Zone::Reserve)
        .child(Rectangle::new().width(Parent).height(Parent).fill(Color::BLACK))
}
```

Это настоящий бар: во всю ширину, высотой 32 пикселя, прикреплён к верху, выше обычных окон, и другие окна не занимают его 32 пикселя.

### Как настройки окна доходят до композитора

Композитор (niri, Hyprland, Sway) владеет экраном. `LayerWindow` — это запрос к нему: «помести это на верхний край, такого размера, на такой слой». Каждый метод задаёт часть запроса:

- `width` и `height` идут первыми и обязательны. Число — размер в пикселях. `Full` растягивает окно на весь монитор.
- `anchor_vertical` и `anchor_horizontal` выбирают края, к которым окно прикрепляется.
- `layer` выбирает высоту в стеке.
- `space` решает, должны ли другие окна обходить его.

Представление выполняется заново при каждом изменении, и Amane сравнивает новые настройки со старыми. Если что-то изменилось, композитору отправляется только изменение. Поэтому окно можно двигать, менять в размере или скрывать, просто возвращая другие настройки из `view`.

### Размер

```rust
LayerWindow::new().width(300.0).height(200.0)   // 300 на 200 пикселей
LayerWindow::new().width(Full).height(30.0)     // вся ширина, высота 30
LayerWindow::new().width(48.0).height(Full)     // вся высота, боковая панель
```

`width` должен идти перед `height`, а оба — перед остальными методами. Если забыть один, код не скомпилируется: открыть окно без размера нельзя.

Композитор может дать окну не тот размер, который он просил. Чтобы узнать реальный, используйте `window_size()` внутри представления.

### Позиция

```rust
.anchor_vertical(Vertical::Top)          // Top, Middle или Bottom
.anchor_horizontal(Horizontal::Right)    // Left, Middle или Right
```

Оба по умолчанию `Middle`, поэтому окно без якорей находится в центре экрана.

Размер `Full` сам прикрепляет обе противоположные стороны. `Full` по ширине прикреплён к левому и правому краю, что бы ни говорил `anchor_horizontal`.

Чтобы оставить отступ от края, используйте margin. Числа — в пикселях:

```rust
.margin(Margin { top: 10, right: 10, bottom: 0, left: 0 })
```

Margin отталкивает только от того края, к которому окно прикреплено. Отрицательный margin сдвигает окно за край, частично за экран — это удобно для выезжающей панели.

### Слой

```rust
.layer(Layer::Top)
```

| Слой | Где находится | Для чего |
|---|---|---|
| `Background` | под всем | обои |
| `Bottom` | под обычными окнами | виджеты рабочего стола |
| `Top` | над обычными окнами | бары, доки |
| `Overlay` | над всем, даже полноэкранными окнами | всплывающие окна, лаунчеры, OSD |

По умолчанию — `Overlay`. Для бара ставьте `Top`, иначе он будет перекрывать полноэкранное видео.

### Зарезервированное место

```rust
.space(Zone::Reserve)
```

| Зона | Эффект |
|---|---|
| `Reserve` | другие окна не занимают полосу, которую покрывает это окно. Для баров. |
| `Respect` | ничего не резервирует и сам обходит место, зарезервированное другими. По умолчанию. |
| `Ignore` | ничего не резервирует и может перекрывать чужое зарезервированное место. Для полноэкранных оверлеев. |

`Reserve` резервирует высоту окна или его ширину, если окно прикреплено к левому/правому краю и имеет фиксированную ширину.

> **Уточнение.** Если у окна есть margin со стороны, обращённой к другим окнам, этот margin также входит в зарезервированную полосу. Например, верхний бар с `margin.bottom = 4` зарезервирует высоту плюс 4 пикселя.

### Клавиатура

По умолчанию слойное окно не получает клавиш. Чтобы в него можно было печатать, попросите фокус:

```rust
.keyboard(Keyboard::OnDemand)
```

| Клавиатура | Эффект |
|---|---|
| `None` | никогда не получает клавиши. По умолчанию. |
| `OnDemand` | получает клавиши после клика, как обычное окно. Для строки поиска в панели. |
| `Exclusive` | забирает все клавиши, пока открыто. Для лаунчеров и меню. |

О том, что делать с клавишами, — в главе «Ввод».

### Скрытие и показ

```rust
.visible(panel.open)
```

Скрытое окно продолжает существовать. Его представление продолжает выполняться, и оно снова появится, когда представление вернёт `visible(true)`. Так делается панель, переключаемая горячей клавишей.

> **Уточнение.** Пока окно скрыто, его `window_size()` равен `(0.0, 0.0)`: у скрытого окна нет поверхности и конфигурации. Не используйте размер скрытого окна для вычислений, которые должны пережить показ.

### Клики, проходящие сквозь окно

По умолчанию всё окно принимает мышь. Чтобы клики доходили до окон под ним:

```rust
.click_through()                     // ни одна часть окна не принимает мышь
.input_region(vec![InputArea { x: 0, y: 0, width: 100, height: 30 }])   // только эта часть
```

`InputArea` задаётся в пикселях от левого верхнего угла окна. Можно передать несколько областей; они объединяются.

> **Уточнение.** Координаты `InputArea` — в тех же единицах, что размеры виджетов, то есть до умножения на `App::scale_factor`. При масштабировании области увеличиваются вместе с окном.

### Namespace

```rust
.namespace("bar")
```

Namespace — имя, по которому композитор может применять правила к окну, например `layer-rule` в niri. По умолчанию `"amane"`. Читается только при открытии окна, поэтому изменение позже ничего не делает.

### Термины

- **Layer shell:** протокол Wayland (wlr-layer-shell), который используют слойные окна. Композитор должен его поддерживать.
- **Якорь (anchor):** край, к которому прикреплено окно.
- **Эксклюзивная зона (exclusive zone):** название зарезервированного места в протоколе.

## Компоновка

В баре обычно несколько элементов слева, часы в центре и несколько справа. При изменении ширины бара середина должна растягиваться, а края оставаться того же размера.

Эта глава объясняет, как виджеты получают размер и позицию: `Size`, `Row`, `Column`, `Stack`, отступы и выравнивание.

### Фиксированные и растягивающиеся виджеты

```rust
use amane::{App, Color, Full, LayerWindow, Parent, Rectangle, Row, children};

fn main() {
    App::new().window(view).run();
}

fn view() -> LayerWindow {
    LayerWindow::new()
        .width(Full)
        .height(30.0)
        .child(Row::new(children![
            Rectangle::new().width(100.0).height(Parent).fill(Color::RED),
            Rectangle::new().width(Parent).height(Parent).fill(Color::GREEN),
            Rectangle::new().width(100.0).height(Parent).fill(Color::BLUE),
        ]))
}
```

Красный всегда 100 пикселей, синий всегда 100, зелёный забирает остаток.

### Как `Row` размещает детей

Каждый виджет отвечает на один вопрос для каждого направления: какого размера ты хочешь быть? Ответ — `Size`, и есть два вида:

- **число**, например `100.0`: ровно столько пикселей;
- **`Parent`**: «столько, сколько даст родитель».

`Row` вычисляет позиции в два шага:

1. **Измеряет.** Фиксированным детям нужно 100 + 100 = 200 пикселей. Остаток ширины строки свободен.
2. **Размещает.** Дети ставятся друг за другом. Свободное место делится поровну между `Parent`-детьми. Здесь такой ребёнок один, поэтому зелёный получает всё.

Когда бар становится шире, меняется только свободное место, поэтому растёт только зелёный.

> **Уточнение.** Если фиксированные дети уже не помещаются, свободное место не становится отрицательным: `Parent`-дети получают 0. Переполнение может выйти за границы в зависимости от `justify`.

### Списки виджетов

`Row::new` принимает список виджетов разных типов: прямоугольники, текст, другие строки. Список Rust может хранить только один тип, поэтому каждый виджет упаковывается в `Box<dyn Widget>` — «любой виджет». Макрос `children!` делает это сам:

```rust
Row::new(children![
    Rectangle::new().width(100.0).height(30.0),
    Text::new("hello"),
])
```

Если список строится в цикле, упаковывайте вручную:

```rust
use amane::{App, Column, LayerWindow, Text, Widget};

fn main() {
    App::new().window(view).run();
}

fn view() -> LayerWindow {
    let mut rows: Vec<Box<dyn Widget>> = Vec::new();

    for number in 1..=5 {
        rows.push(Box::new(Text::new(format!("row {number}"))));
    }

    LayerWindow::new().width(200.0).height(200.0).child(Column::new(rows))
}
```

### `Row`, `Column` и `Stack`

| Виджет | Размещение детей |
|---|---|
| `Row` | рядом, слева направо |
| `Column` | друг над другом, сверху вниз |
| `Stack` | все в одном месте; поздние рисуются поверх ранних |

`Row` и `Column` работают одинаково, только в разных направлениях. Всё сказанное о `Row` относится и к `Column`, с заменой ширины на высоту.

`Stack` нужен для наложения, например бейджа на карточке. Каждый ребёнок начинает с левого верхнего угла стека. Сдвинуть его можно через `translate`:

```rust
use amane::{App, Center, Color, Full, LayerWindow, Rectangle, Stack, Text, children};

fn main() {
    App::new().window(view).run();
}

fn view() -> LayerWindow {
    let card = Rectangle::new()
        .width(200.0)
        .height(120.0)
        .radius(16.0)
        .fill("#1e1e2e");

    let badge = Rectangle::new()
        .width(28.0)
        .height(28.0)
        .radius(Full)
        .fill("#f38ba8")
        .translate(186.0, -14.0)
        .align_child(Center, Center)
        .child(Text::new("3").size(14.0).color(Color::BLACK));

    LayerWindow::new()
        .width(260.0)
        .height(180.0)
        .child(Stack::new(children![card, badge]))
}
```

### Какого размера `Row`

Если не задать размер `Row`, он измеряет детей:

- ширина — сумма ширин детей плюс промежутки;
- высота — высота самого высокого ребёнка;
- если хотя бы один ребёнок в этом направлении `Parent`, то и `Row` становится `Parent` в этом направлении.

Чтобы задать размер явно, используйте `.width(...)` и `.height(...)`. Для `Row`, `Column` и `Stack` оба метода необязательны.

### Промежутки

```rust
Row::new(children![a, b, c]).gap(12.0)
```

`gap` добавляет 12 пикселей между каждой парой детей. Перед первым и после последнего промежутка нет.

### Распределение детей вдоль строки

Когда дети не заполняют строку, `justify` решает, куда уйдёт остаток:

```rust
Row::new(children![a, b, c]).width(Parent).justify(SpaceBetween)
```

| `justify` | Эффект |
|---|---|
| `Start` | прижаты к началу. По умолчанию. |
| `Center` | по центру |
| `End` | прижаты к концу |
| `SpaceBetween` | первый в начале, последний в конце, равные промежутки между |
| `SpaceAround` | равное место вокруг каждого ребёнка |
| `SpaceEvenly` | равные промежутки между детьми и краями |

`justify` имеет значение только при наличии свободного места. `Parent`-ребёнок забирает всё, и распределять нечего.

### Выравнивание поперёк строки

`align` решает, где каждый ребёнок стоит в другом направлении. Для `Row` это вертикаль:

```rust
Row::new(children![a, b, c]).height(40.0).align(Center)
```

Принимает `Start`, `Center`, `End`. По умолчанию `Start`: верх строки или левый край столбца.

### Padding и размещение одного ребёнка

`Rectangle` содержит одного ребёнка. `padding` оставляет место между краями и ребёнком, а `align_child` размещает ребёнка внутри этого пространства:

```rust
use amane::{App, Center, Color, End, LayerWindow, Padding, Parent, Rectangle};

fn main() {
    App::new().window(view).run();
}

fn view() -> LayerWindow {
    LayerWindow::new().width(300.0).height(100.0).child(
        Rectangle::new()
            .width(Parent)
            .height(Parent)
            .fill(Color::BLACK)
            .padding(Padding { top: 8.0, right: 16.0, bottom: 8.0, left: 16.0 })
            .align_child(End, Center)
            .child(Rectangle::new().width(40.0).height(40.0).fill(Color::RED)),
    )
}
```

- `padding(16.0)` задаёт одинаковый отступ со всех сторон. `Padding { ... }` задаёт каждую сторону отдельно.
- `align_child(horizontal, vertical)` принимает `Start`, `Center`, `End` для каждого направления. По умолчанию — левый верхний угол.

### Пример: бар из трёх частей

Слева, в центре и справа, причём центр всегда находится посередине бара:

```rust
use amane::{
    Align, App, Center, Color, End, Full, LayerWindow, Parent, Rectangle, Row, Start, Text,
    children,
};

fn main() {
    App::new().window(view).run();
}

fn view() -> LayerWindow {
    LayerWindow::new()
        .width(Full)
        .height(30.0)
        .child(Row::new(children![
            section(Text::new("workspaces").color(Color::WHITE), Start),
            section(Text::new("12:00").color(Color::WHITE), Center),
            section(Text::new("battery").color(Color::WHITE), End),
        ]))
}

fn section(content: Text, align: impl Into<Align>) -> Rectangle {
    Rectangle::new()
        .width(Parent)
        .height(Parent)
        .fill("#1e1e2e")
        .align_child(align, Center)
        .child(content)
}
```

Все три секции имеют размер `Parent`, поэтому каждая получает ровно треть бара. Средняя треть всегда центрирована, какой бы длины ни был текст слева и справа.

### Термины

- **Size:** фиксированное число пикселей или `Parent`.
- **Justify:** размещение вдоль направления роста строки или столбца.
- **Align:** размещение поперёк этого направления.
- **Главная и поперечная оси:** обычные названия для «вдоль» и «поперёк».

## Масштабирование

Задайте коэффициент масштаба у `App`, чтобы сделать всю оболочку больше или меньше:

```rust
App::new().scale_factor(1.4).window(bar).run();
```

По умолчанию — `1.0`. Коэффициент должен быть положительным и конечным; недопустимое значение паникует при вызове `scale_factor`.

Все слойные окна, обычные окна и экраны блокировки используют один коэффициент, включая окна, открытые позже. Размеры виджетов, текст, отступы, рамки, эффекты, отступы окон, зарезервированное место и области ввода масштабируются вместе. Бар высотой `30.0` запрашивает 42 пикселя поверхности при коэффициенте `1.4`. `Full` по-прежнему заполняет монитор.

Масштаб монитора в композиторе также применяется. На мониторе с масштабом `1.25` и коэффициентом приложения `1.4` на одну единицу виджета приходится `1.75` физического пикселя. Amane держит буфер в разрешении монитора, поэтому не масштабирует готовую картинку второй раз.

`window_size()` и размеры `Monitor` выражаются в единицах виджетов, до коэффициента приложения. Движение указателя и координаты в `on_drag` — тоже, включая transformed-виджеты. Один и тот же код представления работает при любом масштабе. Размеры монитора округляются до целых единиц; используйте `Full`, если окно должно точно растягиваться между краями монитора.

### Выбор масштаба при запуске

Коэффициент задаётся при старте приложения. Чтобы менять его из скрипта без правки оболочки, прочитайте переменную окружения в `main`:

```rust
let factor = std::env::var("AMANE_SCALE_FACTOR")
    .map(|value| value.parse::<f32>().expect("invalid AMANE_SCALE_FACTOR"))
    .unwrap_or(1.0);

App::new().scale_factor(factor).window(bar).run();
```

Затем запустите оболочку с `AMANE_SCALE_FACTOR=1.4`. Для другого коэффициента перезапустите её. Переменная читается именно этим примером кода, а не самой библиотекой.

> **Уточнение.** В оригинале сказано «Amane scales all windows and widgets». Точнее: коэффициент влияет на запрашиваемые размеры и раскладку, а физический масштаб монитора добавляется композитором. Итоговое число физических пикселей на единицу виджета равно `app_factor × monitor_scale`.

## Состояние и сервисы

Представление перестраивается каждый кадр, поэтому не может хранить данные. Для этого есть **сервис**. Он хранит значение между кадрами, обновляет его в фоне и перерисовывает окна, которые его показывают, когда значение меняется.

В этой главе: как читать сервис, как написать свой и какие правила действуют.

### Часы

```rust
use std::time::Duration;

use amane::{App, Full, LayerWindow, Service, Text};

struct Clock {
    time: String,
}

impl Service for Clock {
    fn new() -> Self {
        Self { time: amane::output("date +%H:%M:%S") }
    }

    fn interval() -> Duration {
        Duration::from_secs(1)
    }

    fn update(&mut self) -> bool {
        let time = amane::output("date +%H:%M:%S");

        let changed = time != self.time;

        self.time = time;

        changed
    }
}

fn main() {
    App::new().window(view).run();
}

fn view() -> LayerWindow {
    let clock = Clock::read();

    LayerWindow::new()
        .width(Full)
        .height(30.0)
        .child(Text::new(&clock.time))
}
```

`std::time::Duration` — из стандартной библиотеки Rust. `amane::output` запускает команду оболочки и возвращает то, что она напечатала.

### Как обновляется сервис

1. При первом вызове `Clock::read()` Amane создаёт часы через `new()` и хранит их, пока работает оболочка. `Clock` существует в единственном экземпляре.
2. Amane запускает отдельный фоновый поток для часов. Каждый `interval()` этот поток вызывает `update()`.
3. `update()` возвращает, изменилось ли что-то, что показывают окна. Если `true`, Amane перерисовывает все окна, чьи представления читали часы.
4. `view` вызывает `Clock::read()`, получает текущее значение и записывает, что окно зависит от часов.

Поток часов выполняет ожидание, поэтому бар не замерзает, даже если `date` медленная.

### Чтение сервиса

```rust
let clock = Clock::read();
```

`read()` работает откуда угодно: из представлений, обработчиков ввода, других сервисов. В представлении он ещё и подписывает окно на сервис, из-за чего окно перерисовывается при изменениях.

Возвращаемое значение блокирует сервис на чтение. Держите его столько, сколько нужно, затем отпустите. В представлении это обычно до конца функции.

### Запись в сервис

```rust
Counter::write().count += 1;
```

`write()` даёт сервис для изменения. Когда возвращённое значение исчезает (в этом примере — в конце инструкции), Amane помечает сервис изменённым и перерисовывает все окна, которые его читают. Ничего вызывать для перерисовки не нужно.

Пишите из обработчиков ввода, IPC-обработчиков или из собственного потока сервиса.

> **Никогда не вызывайте `write()` внутри представления.** Представление может всё ещё держать `read()` того же сервиса, а запись ждёт завершения всех чтений — оболочка зависнет навсегда. Представление только читает.

> **Уточнение.** `write()` считается изменением даже если вы записали то же самое значение. Не делайте запись в цикле без необходимости: это лишние перерисовки.

### Состояние, которое меняется только вводом

Многие сервисы ничего не опрашивают. Открыто ли меню, счётчик, выбранная вкладка — всё это меняется только по клику. Задайте им большой интервал и не реализуйте `update`:

```rust
use std::time::Duration;

use amane::{App, Button, LayerWindow, Parent, Rectangle, Service, Text};

struct Counter {
    count: i32,
}

impl Service for Counter {
    fn new() -> Self {
        Self { count: 0 }
    }

    // само по себе ничего не меняется, только по кликам
    fn interval() -> Duration {
        Duration::from_secs(3600)
    }
}

fn main() {
    App::new().window(view).run();
}

fn view() -> LayerWindow {
    let counter = Counter::read();

    LayerWindow::new().width(200.0).height(40.0).child(
        Rectangle::new()
            .width(Parent)
            .height(Parent)
            .fill("#1e1e2e")
            .on_click(clicked)
            .child(Text::new(format!("clicked {} times", counter.count))),
    )
}

fn clicked(_: Button) {
    Counter::write().count += 1;
}
```

`update` по умолчанию возвращает «ничего не изменилось», поэтому опрос ничего не стоит.

### Ожидание вместо опроса

Некоторые данные сами сообщают об изменениях: команда, печатающая события, сохранение файла, сигнал D-Bus. Опрос таких источников тратит время и добавляет задержку. Вместо этого замените `listen`:

```rust
use amane::{App, Full, LayerWindow, Service, Text};

struct Niri {
    event: String,
}

impl Service for Niri {
    fn new() -> Self {
        Self { event: String::from("waiting for niri") }
    }

    fn listen() {
        for line in amane::lines("niri msg event-stream") {
            Self::write().event = line;
        }
    }
}

fn main() {
    App::new().window(view).run();
}

fn view() -> LayerWindow {
    let niri = Niri::read();

    LayerWindow::new().width(Full).height(30.0).child(Text::new(&niri.event))
}
```

`listen` выполняется в собственном потоке сервиса, поэтому может ждать сколько угодно. Стандартный `listen` — это цикл опроса из раздела «Как обновляется сервис». Если заменить его, `interval` и `update` больше не используются.

Если `listen` паникует, например потому что программа, с которой он общается, завершилась, Amane печатает сообщение и запускает его снова через 5 секунд. Если `listen` возвращается нормально, сервис сохраняет последнее значение и перестаёт обновляться.

### Несколько сервисов в одном представлении

Представление может читать сколько угодно сервисов:

```rust
let battery = Battery::read();
let audio = Audio::read();
let clock = Clock::read();
```

Окно перерисуется при изменении любого из них. Окно, которое не читает ни один из них, из-за них не перерисовывается. Так оболочка с множеством окон остаётся дешёвой: каждое окно просыпается только для своих данных.

### Встроенные сервисы

Amane включает сервисы для типичных системных данных: `Battery`, `Audio`, `Network`, `Media`, `Notifications`, `Workspaces` и другие. Они используются так же, как собственные, через `read()`, и имеют функции управления вроде `Audio::set_volume(50)`.

### Термины

- **Сервис:** одно глобальное значение на тип, со своим фоновым потоком. Чтение в представлении подписывает окно.
- **Опрос (poll):** запрос новых данных по таймеру через `interval` и `update`.
- **Ожидание (listen):** ожидание прихода данных через замену `listen`.

## Ввод

Бару нужны кнопки: клик по рабочему столу переключает его, прокрутка над громкостью меняет звук, клик по часам открывает календарь.

В этой главе: клики, наведение, прокрутка, перетаскивание, вид указателя и клавиши.

### Обработка клика

```rust
use amane::{App, Button, LayerWindow, Parent, Rectangle, Text};

fn main() {
    App::new().window(view).run();
}

fn view() -> LayerWindow {
    LayerWindow::new().width(200.0).height(40.0).child(
        Rectangle::new()
            .width(Parent)
            .height(Parent)
            .fill("#1e1e2e")
            .on_click(clicked)
            .child(Text::new("click me")),
    )
}

fn clicked(button: Button) {
    println!("clicked with {button:?}");
}
```

### Как ввод доходит до обработчика

Обработчики ввода задаются у `Rectangle`. Каждый кадр Amane запоминает, где оказался каждый прямоугольник с обработчиком. При клике он находит прямоугольник под указателем и вызывает его обработчик.

Если прямоугольники перекрываются, событие получает нарисованный последним. Это самый внутренний и верхний: кнопка внутри панели получает клик, а не панель.

Обработчик выполняется после исчезновения кадра, поэтому не может менять виджеты напрямую. Он меняет состояние, обычно записывая в сервис, а представление показывает изменение на следующем кадре:

```rust
fn clicked(_: Button) {
    Counter::write().count += 1;
}
```

### Обработчики мыши

Все это методы `Rectangle`:

| Метод | Когда вызывается | Что получает |
|---|---|---|
| `on_click` | кнопка нажата и отпущена над одним и тем же прямоугольником | `Button`: `Left`, `Right` или `Middle` |
| `on_hover` | когда указатель входит и когда выходит | `true` при входе, `false` при выходе |
| `on_scroll` | на каждый шаг колеса или движение тачпада | `Scroll` с `x` и `y` |
| `on_move` | при каждом движении, пока указатель над прямоугольником | `Point` |
| `on_drag` | при нажатии левой кнопкой и при каждом движении до отпускания | `Point` |

`Point` содержит `x` и `y` в пикселях от левого верхнего угла прямоугольника. Во время `on_drag` точка продолжает приходить даже после выхода указателя за прямоугольник, поэтому она может быть отрицательной или больше размеров. Ограничивайте её.

`Scroll` измеряется в строках, поэтому колесо и тачпад двигают на одинаковую величину. Положительный `y` — вниз, положительный `x` — вправо.

### Передача значений в обработчики

Обработчик может быть функцией, как `clicked` выше, или замыканием. Замыкание может перенести значения из представления:

```rust
use amane::{App, Column, LayerWindow, Parent, Rectangle, Text, Widget};

fn main() {
    App::new().window(view).run();
}

fn view() -> LayerWindow {
    let mut rows: Vec<Box<dyn Widget>> = Vec::new();

    for number in 1..=3 {
        let row = Rectangle::new()
            .width(Parent)
            .height(30.0)
            .on_click(move |_| println!("clicked row {number}"))
            .child(Text::new(format!("row {number}")));

        rows.push(Box::new(row));
    }

    LayerWindow::new().width(200.0).height(90.0).child(Column::new(rows))
}
```

`move` копирует `number` в замыкание, поэтому каждая строка помнит свой номер. `|_|` игнорирует аргумент `Button`.

Замыкание не может заимствовать данные из `read()` сервиса, потому что обработчик живёт дольше представления. Сначала скопируйте нужное:

```rust
let id = workspace.id();                                   // копия, не заимствование
let name = String::from(device.name());                    // собственная копия текста

Rectangle::new()
    .width(30.0)
    .height(Parent)
    .on_click(move |_| Workspaces::focus(id))
```

### Эффект наведения

Для эффекта наведения нужно состояние: представление должно знать, находится ли указатель внутри:

```rust
use std::time::Duration;

use amane::{App, Color, LayerWindow, Parent, Rectangle, Service};

struct Hover {
    inside: bool,
}

impl Service for Hover {
    fn new() -> Self {
        Self { inside: false }
    }

    fn interval() -> Duration {
        Duration::from_secs(3600)
    }
}

fn main() {
    App::new().window(view).run();
}

fn view() -> LayerWindow {
    let hover = Hover::read();

    let fill = if hover.inside { Color::from("#45475a") } else { Color::from("#1e1e2e") };

    LayerWindow::new().width(200.0).height(40.0).child(
        Rectangle::new()
            .width(Parent)
            .height(Parent)
            .fill(fill)
            .on_hover(|inside| Hover::write().inside = inside),
    )
}
```

### Изменение указателя

```rust
Rectangle::new()
    .width(100.0)
    .height(30.0)
    .cursor(Pointer)
    .on_click(clicked)
```

Пока указатель над прямоугольником, он выглядит соответствующим образом. Имена импортируются из `amane`: `Default`, `Pointer` (рука), `Text`, `Grab`, `Grabbing`, `Move`, `NotAllowed`, `Wait`, `Crosshair` и стрелки изменения размера `ResizeTop`, `ResizeBottom`, `ResizeLeft`, `ResizeRight`, `ResizeTopLeft`, `ResizeTopRight`, `ResizeBottomLeft`, `ResizeBottomRight`, `ResizeHorizontal`, `ResizeVertical`.

`Text`-курсор и `Text`-виджет имеют одинаковое имя, оба из `amane`. Rust различает их по использованию. Если хотите явно — пишите `Cursor::Text`.

`TextInput` сам показывает текстовый курсор.

### Трансформированные прямоугольники

Ввод следует за трансформацией. Повёрнутая кнопка реагирует только внутри повёрнутой формы, а не внутри прямоугольника, который она занимала до поворота.

### Ввод с клавиатуры

Клавиши приходят окну, а не виджету. Сначала окно должно попросить фокус клавиатуры, затем обрабатывает клавиши через `on_key`:

```rust
use std::process;

use amane::{App, Key, Keyboard, LayerWindow, Text};

fn main() {
    App::new().window(view).run();
}

fn view() -> LayerWindow {
    LayerWindow::new()
        .width(300.0)
        .height(40.0)
        .keyboard(Keyboard::Exclusive)
        .on_key(key_pressed)
        .child(Text::new("press escape to quit"))
}

fn key_pressed(key: Key) {
    if key == Key::Escape {
        process::exit(0);
    }
}
```

`std::process` — из стандартной библиотеки Rust.

`Key` — это одно из:

- `Character(char)`: клавиша, которая что-то печатает, уже с учётом Shift, например `Character('A')`;
- `Enter`, `Escape`, `Tab`, `Backspace`, `Space`;
- `Up`, `Down`, `Left`, `Right`, `Home`, `End`;
- `Other`: любая клавиша, для которой у Amane пока нет имени.

### Когда фокус у `TextInput`

Сфокусированный `TextInput` получает клавиши раньше окна, потому что печатать нужно в поле:

- буквы, `Space`, `Backspace`, `Enter`, `Left`, `Right`, `Home` и `End` идут только в поле;
- `Up`, `Down`, `Tab` и `Other` пропускают поле и идут в `on_key` окна. Так стрелки могут перемещать по списку, пока вы печатаете в поиске;
- `Escape` снимает фокус с поля и затем также передаётся окну, которое может захотеть закрыться.

> **Уточнение.** `Enter` забирается полем всегда. Если у поля нет `on_submit`, нажатие просто ничего не делает и до `on_key` окна не доходит. `Up`/`Down`/`Tab`/`Other` не передаются полю, поэтому в тексте не появляются.

### Термины

- **Обработчик (handler):** функция, которую Amane вызывает при событии.
- **Цель (target):** область, которую прямоугольник с обработчиками занимал в последнем кадре.
- **Фокус клавиатуры:** окно, которому композитор отправляет клавиши.

## Анимация

Когда панель прыгает со 100 пикселей до 400 за один кадр, это выглядит сломанным. Она должна вырастать за долю секунды. Но представление описывает только один кадр и выполняется только при изменениях. Анимации решают обе проблемы.

В этой главе: плавное движение, выезжающие панели, исчезающие всплывающие окна и плавно смешивающиеся цвета.

### Вырастающий прямоугольник

```rust
use std::time::Duration;

use amane::{Animation, App, Button, LayerWindow, Parent, Rectangle, Service};

struct Panel {
    height: Animation,
}

impl Service for Panel {
    fn new() -> Self {
        Self { height: Animation::new(100.0) }
    }

    fn interval() -> Duration {
        Duration::from_secs(3600)
    }
}

fn main() {
    App::new().window(view).run();
}

fn view() -> LayerWindow {
    let panel = Panel::read();

    LayerWindow::new().width(300.0).height(400.0).child(
        Rectangle::new()
            .width(Parent)
            .height(panel.height.value())
            .fill("#89b4fa")
            .on_click(clicked),
    )
}

fn clicked(_: Button) {
    let mut panel = Panel::write();

    let target = if panel.height.value() < 250.0 { 400.0 } else { 100.0 };

    panel.height.to(target);
}
```

Кликните прямоугольник — он плавно вырастет до 400 пикселей. Ещё клик — снова сожмётся.

### Как анимация продолжает рисовать

`Animation` не хранит постоянно меняющееся число. Она хранит начальное значение, цель и время старта. `value()` вычисляет текущее число из часов.

1. `to(400.0)` задаёт новую цель и запоминает время. Так как это происходит внутри `write()`, окно перерисовывается.
2. Представление вызывает `value()`. Анимация только началась, поэтому возвращается около 100.
3. Вызов `value()` у незавершённой анимации также сообщает Amane «я ещё двигаюсь». После отрисовки Amane просит у композитора следующий кадр.
4. На следующем кадре представление снова выполняется, и `value()` возвращает чуть больше.
5. Когда анимация доходит до цели, `value()` перестаёт просить кадры, и окно засыпает.

Так анимация стоит кадров только пока движется. Оболочка с завершёнными анимациями ничего не рисует.

### Скорость и сглаживание

```rust
Animation::new(0.0)
    .duration(Duration::from_millis(400))
    .easing(Easing::InOut)
```

- `duration` по умолчанию 200 миллисекунд.
- `easing` решает, как меняется скорость:

| Сглаживание | Движение |
|---|---|
| `Out` | начинается быстро, замедляется к концу. По умолчанию и подходит для большинства UI. |
| `InOut` | начинается медленно, ускоряется, снова замедляется. Для больших перемещений. |
| `Linear` | одинаковая скорость всё время |

### Смена направления на полпути

Если вызвать `to`, пока анимация ещё движется, она начнёт заново с текущего положения. Скачка не будет. Можно быстро несколько раз нажать переключатель, и панель плавно развернётся.

Вызов `to` с уже текущей целью ничего не делает.

### Анимация цветов

`Animation` работает с `f32` (по умолчанию) и с `Color`:

```rust
struct Tab {
    fill: Animation<Color>,
}

// в new()
fill: Animation::new(Color::from("#1e1e2e")),

// в обработчике наведения
Tab::write().fill.to(Color::from("#45475a"));

// в представлении
.fill(tab.fill.value())
```

Чтобы анимировать собственный тип, реализуйте трейт `Blend`. `blend(from, to, amount)` возвращает значение на `amount` пути от `from` к `to`, где `amount` меняется от 0 до 1.

### Анимация окон

Всё, что возвращает представление, может происходить из анимации, включая размер и margin окна. Панель, выезжающая сверху:

```rust
use std::time::Duration;

use amane::{
    Animation, App, Horizontal, Layer, LayerWindow, Margin, Parent, Rectangle, Service, Vertical,
};

struct Panel {
    open: bool,
    slide: Animation,
}

impl Service for Panel {
    fn new() -> Self {
        Self { open: true, slide: Animation::new(10.0).duration(Duration::from_millis(300)) }
    }

    fn interval() -> Duration {
        Duration::from_secs(3600)
    }
}

fn main() {
    App::new().ipc("toggle", toggle).window(view).run();
}

fn view() -> LayerWindow {
    let panel = Panel::read();

    let margin = Margin { top: panel.slide.value() as i32, right: 10, bottom: 0, left: 0 };

    LayerWindow::new()
        .width(300.0)
        .height(100.0)
        .anchor_vertical(Vertical::Top)
        .anchor_horizontal(Horizontal::Right)
        .layer(Layer::Top)
        .margin(margin)
        .child(Rectangle::new().width(Parent).height(Parent).fill("#89b4fa"))
}

fn toggle(_: &[String]) -> String {
    let mut panel = Panel::write();

    panel.open = !panel.open;

    let target = if panel.open { 10.0 } else { -110.0 };

    panel.slide.to(target);

    String::from("ok")
}
```

`amane ipc call toggle` сдвигает панель вверх за край экрана (отрицательный margin) и возвращает обратно при следующем вызове.

### Движение, которым управляете вы

Некоторое движение никогда не заканчивается: спиннер, пульсирующая точка. Для него вычисляйте позицию из времени сами и вызывайте `request_frame()`, чтобы попросить следующий кадр:

```rust
use std::sync::LazyLock;
use std::time::Instant;

use amane::{App, Full, LayerWindow, Rectangle};

static START: LazyLock<Instant> = LazyLock::new(Instant::now);

fn main() {
    App::new().window(view).run();
}

fn view() -> LayerWindow {
    let seconds = START.elapsed().as_secs_f32();

    let x = 170.0 + (seconds * 3.0).sin() * 150.0;

    // движение никогда не заканчивается, поэтому всегда нужен следующий кадр
    amane::request_frame();

    LayerWindow::new().width(400.0).height(60.0).child(
        Rectangle::new()
            .width(60.0)
            .height(60.0)
            .radius(Full)
            .fill("#89b4fa")
            .translate(x, 0.0),
    )
}
```

`LazyLock` и `Instant` — из стандартной библиотеки Rust.

Перестаньте вызывать `request_frame()`, когда движение закончилось, чтобы окно могло уснуть. Представление, которое вызывает его всегда, будет перерисовываться с частотой монитора бесконечно.

### Термины

- **Сглаживание (easing):** кривая, отображающая прошедшее время в пройденное расстояние.
- **Frame callback:** сигнал композитора, что он готов к следующему кадру. Amane ждёт его, поэтому анимации идут с частотой обновления монитора.

# Часть III. Виджеты

## Rectangle

`Rectangle` — самый используемый виджет. Это прямоугольник, который можно закрасить, скруглить, обвести, оттенить и трансформировать; внутри него может быть один ребёнок. Кнопки, карточки, фоны и иконки — всё это прямоугольники.

### Скруглённый прямоугольник

```rust
use amane::{App, LayerWindow, Rectangle};

fn main() {
    App::new().window(view).run();
}

fn view() -> LayerWindow {
    LayerWindow::new()
        .width(200.0)
        .height(100.0)
        .child(Rectangle::new().width(160.0).height(60.0).radius(12.0).fill("#89b4fa"))
}
```

`width` и `height` обязательны и должны идти первыми, именно в таком порядке. Они принимают число пикселей или `Parent`. Остальное необязательно.

### Заливка

`fill` принимает:

| Заливка | Пример |
|---|---|
| hex-строка | `.fill("#1e1e2e")`, также `"#rgb"` и `"#rrggbbaa"` |
| `Color` | `.fill(Color::BLUE)`, `.fill(Color::rgb(30, 30, 46))`, `.fill(Color::rgba(0, 0, 0, 128))` |
| `Gradient` | `.fill(Gradient::linear(90.0, [(0.0, "#89b4fa"), (1.0, "#f5c2e7")]))` |
| `Image` | `.fill(Image::cover("/path/to/wallpaper.png"))` |
| `Mask` | `.fill(Mask)` — отверстие |

Прямоугольник без заливки невидим. Это полезно для отступов и невидимых областей клика. Если у него есть ребёнок, ребёнок всё равно рисуется.

Опечатка в hex-строке, например `"#12345"`, показывает ярко-розовый цвет вместо падения оболочки, чтобы ошибку было легко заметить.

`Color` содержит константы `BLACK`, `WHITE`, `RED`, `GREEN`, `BLUE` и `TRANSPARENT`. `Color::rgb` и `Color::rgba` — `const`, поэтому тему можно хранить в константах:

```rust
const BACKGROUND: Color = Color::rgb(0x1e, 0x1e, 0x2e);
const FOREGROUND: Color = Color::rgb(0xcd, 0xd6, 0xf4);
```

### Градиенты

```rust
Gradient::linear(90.0, [(0.0, "#89b4fa"), (1.0, "#f5c2e7")])
Gradient::radial([(0.0, "#f9e2af"), (0.5, "#fab387"), (1.0, "#1e1e2e")])
```

Каждая остановка — позиция от 0 до 1 и цвет. Линейный градиент также принимает угол в градусах, как в CSS: `0.0` — снизу вверх, `90.0` — слева направо, `180.0` — сверху вниз.

> **Исправление.** В оригинале сказано, что радиальный градиент идёт «до краёв». На самом деле его радиус доходит до углов прямоугольника. На вытянутом прямоугольнике это заметно: у углов цвет уже конечный, а у середины длинной стороны — ещё нет.

### Углы и рамки

```rust
.radius(12.0)            // скругление 12 пикселей
.radius(Full)            // таблетка или круг, если прямоугольник квадратный
.border(2.0, "#cdd6f4")  // обводка 2 пикселя по внутреннему краю
```

`Full` делает радиус равным половине меньшей стороны, поэтому прямоугольник остаётся идеальной таблеткой при любом размере.

Отдельные углы задаются методами `radius_top_left`, `radius_top_right`, `radius_bottom_right`, `radius_bottom_left`. Незаданные углы остаются прямыми.

> **Уточнение.** Нельзя смешивать `.radius(...)` и отдельные углы в одном прямоугольнике: это паникует. Выбирайте один способ.

### Прозрачность, тень и размытие

```rust
.opacity(0.5)
.shadow(Shadow::drop("#000000").opacity(0.3).blur(12.0).offset(0.0, 4.0))
.shadow(Shadow::inner("#000000").opacity(0.3).blur(8.0))
.blur(20.0)
```

- `opacity` делает прозрачным прямоугольник **и всё внутри него**, от 0 (невидимо) до 1.
- `Shadow::drop` отбрасывает тень за прямоугольником. `Shadow::inner` затеняет внутренний край, как будто прямоугольник вдавлен. `blur` смягчает тень, `offset` сдвигает.
- `blur` размывает то, что было нарисовано за прямоугольником, внутри его формы, для эффекта матового стекла. Он может размыть только то, что нарисовало ваше собственное окно. Окна других приложений ему недоступны.

### Маски

Прямоугольник с заливкой `Mask` ничего не рисует. Вместо этого он вырезает свою форму из ближайшего прямоугольника вокруг:

```rust
use amane::{App, Center, Full, LayerWindow, Mask, Parent, Rectangle};

fn main() {
    App::new().window(view).run();
}

fn view() -> LayerWindow {
    LayerWindow::new().width(200.0).height(120.0).child(
        Rectangle::new()
            .width(Parent)
            .height(Parent)
            .radius(24.0)
            .fill("#1e1e2e")
            .align_child(Center, Center)
            .child(Rectangle::new().width(60.0).height(60.0).radius(Full).fill(Mask)),
    )
}
```

В окне появляется круглая дыра, через которую видно обои. У маски может быть `border`, чтобы обвести отверстие.

> **Уточнение.** Маска вырезает отверстие в ближайшем окружающем прямоугольнике, а не в произвольном окне. Если нужна дыра в другом элементе, вложите маску в него.

### Ребёнок

```rust
Rectangle::new()
    .width(Parent)
    .height(Parent)
    .padding(8.0)
    .align_child(Center, Center)
    .clip()
    .child(Text::new("hello"))
```

- `child` помещает один виджет внутрь. Чтобы разместить несколько, дайте ему `Row`, `Column` или `Stack`.
- `padding` и `align_child` размещают ребёнка.
- `clip` скрывает часть ребёнка, выходящую за края, с учётом скруглений. Используйте для списков и индикаторов прогресса.

### Трансформации

```rust
.rotate(30.0)          // градусы, по часовой стрелке
.scale(0.6)            // 1.0 сохраняет размер
.translate(20.0, -30.0)
```

Поворот и масштаб происходят вокруг центра прямоугольника. Трансформации двигают отрисовку и область клика, но не компоновку: прямоугольник по-прежнему занимает исходное место в строке или столбце, соседи не сдвигаются. Поэтому они хороши для анимации и наложений в `Stack`.

Ребёнок движется вместе с прямоугольником.

### Ввод

`on_click`, `on_hover`, `on_scroll`, `on_move`, `on_drag`, `on_drop` и `cursor` описаны в главе «Ввод».

> **Уточнение.** В книге не был описан `on_drop`, хотя метод есть в API. Он получает файлы, перетащенные из другой программы и отпущенные над прямоугольником:
>
> ```rust
> use std::path::PathBuf;
>
> use amane::{App, Center, LayerWindow, Parent, Rectangle, Text};
>
> fn main() {
>     App::new().window(view).run();
> }
>
> fn view() -> LayerWindow {
>     LayerWindow::new().width(400.0).height(200.0).child(
>         Rectangle::new()
>             .width(Parent)
>             .height(Parent)
>             .fill("#1e1e2e")
>             .align_child(Center, Center)
>             .on_drop(|files: Vec<PathBuf>| {
>                 for file in files {
>                     println!("dropped {}", file.display());
>                 }
>             })
>             .child(Text::new("drop files here")),
>     )
> }
> ```
>
> Поддерживается перетаскивание файлов; текст и другие MIME-типы через этот обработчик не передаются.

### Шейдеры

`.shader("path/to/file.wgsl")` рисует GPU-шейдер поверх заливки. Подробнее — в главе «Шейдеры».

### Пример: кнопка

```rust
use amane::{App, Center, Color, LayerWindow, Pointer, Rectangle, Shadow, Text};

fn main() {
    App::new().window(view).run();
}

fn view() -> LayerWindow {
    LayerWindow::new().width(200.0).height(80.0).child(button("Save"))
}

fn button(label: &str) -> Rectangle {
    Rectangle::new()
        .width(120.0)
        .height(36.0)
        .radius(8.0)
        .fill("#89b4fa")
        .shadow(Shadow::drop("#000000").opacity(0.25).blur(8.0).offset(0.0, 2.0))
        .align_child(Center, Center)
        .cursor(Pointer)
        .on_click(|_| println!("saved"))
        .child(Text::new(label).color(Color::from("#1e1e2e")))
}
```

## Text

`Text` рисует одну или несколько строк текста. В этой главе: размер, цвет, шрифты, насыщенность и поведение, когда текст не помещается.

### Рисование текста

```rust
use amane::{App, Color, LayerWindow, Text};

fn main() {
    App::new().window(view).run();
}

fn view() -> LayerWindow {
    LayerWindow::new()
        .width(300.0)
        .height(40.0)
        .child(Text::new("hello").size(20.0).color(Color::WHITE))
}
```

`Text::new` принимает `&str`, `String` или что угодно, что превращается в `String`, поэтому `format!` работает напрямую:

```rust
Text::new(format!("battery {}%", battery.percent()))
```

По умолчанию: размер 16, чёрный цвет, обычная насыщенность и системный шрифт `sans-serif`.

### Цвет

```rust
Text::new("hello").color(Color::WHITE)
Text::new("hello").color(Color::from("#cdd6f4"))
```

`color` принимает `Color`. В отличие от `Rectangle::fill`, hex-строка напрямую не принимается, поэтому оборачивайте её в `Color::from`.

### Шрифты

Шрифты ищутся через fontconfig, поэтому подходит любой установленный шрифт — по имени семейства:

```rust
App::new().font("Inter").window(view).run()   // по умолчанию для всего текста
Text::new("12:00").font("JetBrains Mono")      // только для этого текста
```

Если символа нет в шрифте, например японского текста в латинском шрифте, Amane ищет его в Noto Sans, затем в Noto Sans CJK JP. Символ, которого нет ни в одном установленном шрифте, пропускается.

### Насыщенность

```rust
Text::new("bold").weight(Weight::Bold)
Text::new("light").weight(300)
```

`Weight` содержит `Thin`, `ExtraLight`, `Light`, `Regular`, `Medium`, `SemiBold`, `Bold`, `ExtraBold` и `Black`. Число от 100 до 900 выбирает ближайшее, как в CSS. В шрифте должно быть установлено соответствующее начертание: большинство семейств поставляются отдельными файлами на каждый вес.

> **Уточнение.** Число округляется до сотни: `650` даст `SemiBold`, `700` — `Bold`, значения выше 900 — `Black`. Это выбор именованного начертания, а не произвольная вариативная ось.

### Длинный текст: обрезка и перенос

По умолчанию текст занимает одну строку и ровно столько ширины, сколько нужно буквам. В `Row` он забирает необходимое место, а соседи с `Parent` получают остаток.

Если текст длиннее отведённого места, он выходит за край. Это меняют два параметра:

```rust
Text::new(long).elide()                     // одна строка, обрезка с "…"
Text::new(long).wrap()                      // столько строк, сколько нужно
Text::new(long).wrap().max_lines(2).elide() // до двух строк, затем "…"
```

С `wrap` или `elide` ширина текста становится `Parent`: он занимает всю данную ширину и вписывается в неё. Поэтому размещайте его там, где ширина задана: в прямоугольнике фиксированной ширины или в `Parent`-секции строки.

Высота зависит от правил:

| Правила | Высота |
|---|---|
| ни одного | одна строка |
| `wrap` с `max_lines(n)` | `n` строк |
| `wrap` без ограничения | `Parent`, потому что число строк зависит от ширины, а она известна только после компоновки |

Если нужна высота перенесённого текста, например для карточки уведомления, запросите её с шириной:

```rust
let body = Text::new(notification.body()).wrap();

let height = body.height_in(360.0);
```

> **Уточнение.** `max_lines` без `wrap` не создаёт перенос: текст остаётся одной строкой, а ограничение строк в основном влияет на высоту. Используйте `max_lines` вместе с `wrap`.

### Иконочные шрифты

Обычно текст измеряется по месту, которое буквы занимают при наборе, включая небольшие поля по бокам. У иконочных шрифтов из-за этого иконка выглядит немного смещённой. `tight` измеряет реальные контуры букв:

```rust
Text::new("\u{f240}").font("Symbols Nerd Font").size(18.0).tight()
```

### Пример

```rust
use amane::{App, Column, LayerWindow, Text, Weight, children};

fn main() {
    App::new().window(view).run();
}

fn view() -> LayerWindow {
    let long = "the quick brown fox jumps over the lazy dog, then keeps running far past the edge";

    LayerWindow::new()
        .width(260.0)
        .height(400.0)
        .child(Column::new(children![
            Text::new("regular"),
            Text::new("bold").weight(Weight::Bold),
            Text::new("light, picked by number").weight(300),
            Text::new(long).elide(),
            Text::new(long).wrap().max_lines(2).elide(),
            Text::new(long).wrap(),
        ]))
}
```

> **Уточнение.** У `Text` нет автоматического переноса по словам «из коробки»: без `wrap` длинная строка выходит за границы, пока её не обрежет `clip` родителя. Для карточек и уведомлений почти всегда нужен `wrap()`.

## TextInput

`TextInput` — однострочное поле ввода: поиск, пароль, командная строка.

### Поле ввода

```rust
use amane::{App, Keyboard, LayerWindow, Rectangle, TextInput};

fn main() {
    App::new().window(view).run();
}

fn view() -> LayerWindow {
    LayerWindow::new()
        .width(300.0)
        .height(40.0)
        .keyboard(Keyboard::OnDemand)
        .child(
            Rectangle::new()
                .width(300.0)
                .height(40.0)
                .fill("#ffffff")
                .padding(8.0)
                .child(
                    TextInput::new("name")
                        .placeholder("your name")
                        .on_submit(|text| println!("hello, {text}")),
                ),
        )
}
```

Кликните поле, напечатайте текст и нажмите Enter.

### Фокус и сохранённый текст

- Окно просит фокус клавиатуры через `.keyboard(Keyboard::OnDemand)`. Без этого композитор не отправляет окну клавиши, и поле нельзя набрать.
- Клик по полю даёт ему фокус. Дальше набранные клавиши идут в него.
- Представление перестраивается каждый кадр, поэтому поле не может хранить свой текст. Amane хранит его под именем, переданным в `TextInput::new`, здесь `"name"`. У каждого поля должно быть своё имя.

> **Уточнение.** Имена полей глобальны для процесса. Два поля с одинаковым именем делят текст, курсор и фокус. То же относится к именам `ScrollArea`.

### Параметры

```rust
TextInput::new("search")
    .size(18.0)                       // размер текста, по умолчанию 16
    .color(Color::WHITE)              // цвет текста, по умолчанию чёрный
    .width(240.0)                     // по умолчанию Parent
    .placeholder("search apps")       // показывается, пока поле пустое
    .password()                       // показывает • вместо текста
    .focused()                        // берёт клавиши сразу при отрисовке, без клика
    .on_change(|text| ...)            // после каждого изменения, с полным новым текстом
    .on_submit(|text| ...)            // по Enter
```

`focused` подходит для лаунчера: открыли — сразу печатаете. Используйте его вместе с `Keyboard::Exclusive` у окна.

> **Исправление.** `.focused()` вызывается при каждой отрисовке поля и каждый раз заново назначает фокус. Если таких полей несколько, фокус будет у последнего; поле с `.focused()` может отобрать фокус у поля, выбранного кликом. Используйте `.focused()` только для одного поля.

Текст длиннее поля обрезается по его краю. Поле однострочное: `wrap` и многострочный ввод не поддерживаются.

### Чтение введённого текста

Поле владеет текстом. Чтобы использовать его в другом месте, скопируйте текст в сервис в `on_change`:

```rust
use std::time::Duration;

use amane::{App, Column, Keyboard, LayerWindow, Service, Text, TextInput, children};

struct Search {
    query: String,
}

impl Service for Search {
    fn new() -> Self {
        Self { query: String::new() }
    }

    fn interval() -> Duration {
        Duration::from_secs(3600)
    }
}

fn main() {
    App::new().window(view).run();
}

fn view() -> LayerWindow {
    let search = Search::read();

    LayerWindow::new()
        .width(300.0)
        .height(80.0)
        .keyboard(Keyboard::Exclusive)
        .child(Column::new(children![
            TextInput::new("search")
                .focused()
                .on_change(|text| Search::write().query = text),
            Text::new(format!("searching for: {}", search.query)),
        ]))
}
```

### Установка текста

`TextInput::set_text` заменяет текст поля по имени и ставит курсор в конец:

```rust
TextInput::set_text("search", "");          // очистить, например после Enter
TextInput::set_text("search", "firefox");   // заполнить
```

> **Уточнение.** `set_text` не вызывает `on_change`. Если вы синхронизируете поле с сервисом, обновляйте сервис вручную.

Для обычного поля Enter сам ничего не очищает — вызовите `set_text` в `on_submit`, если это нужно. Для парольного поля действует особое правило, см. ниже.

### Клавиши

Пока поле в фокусе:

- буквы, `Space`, `Backspace`, `Left`, `Right`, `Home` и `End` редактируют текст;
- `Enter` вызывает `on_submit`;
- `Escape` снимает фокус, а затем клавиша доходит до `on_key` окна;
- `Up`, `Down` и `Tab` пропускают поле и идут прямо в `on_key` окна, чтобы можно было двигаться по списку под поиском.

Удержание клавиши пока не вызывает автоповтор. Выделения текста, копирования и вставки в `TextInput` нет.

### Парольные поля

```rust
TextInput::new("password")
    .placeholder("password")
    .password()
    .on_submit(|password| Lock::unlock(&password))
```

`password` меняет только отрисовку: вместо символов рисуется `•`. Текст, переданный в `on_change` и `on_submit`, — настоящий.

> **Исправление.** Оригинал утверждает, что Enter не очищает поле само по себе. Для парольного поля с `on_submit` это не так: `submit` сначала вызывает обработчик, а затем очищает поле. Обработчик получает настоящий пароль, но после его возврата текст уже пуст. Если вызвать `set_text` внутри обработчика, автоматическая очистка всё равно перезапишет результат.
>
> Если `on_submit` не задан, Enter не очищает поле и вообще ничего не делает: клавиша забирается полем и до окна не доходит.

## ScrollArea

`ScrollArea` показывает часть виджета, который выше отведённого места, и прокручивает его колесом мыши или тачпадом.

### Прокручиваемый список

```rust
use amane::{App, Column, LayerWindow, Rectangle, ScrollArea, Text, Widget};

fn main() {
    App::new().window(view).run();
}

fn view() -> LayerWindow {
    let mut rows: Vec<Box<dyn Widget>> = Vec::new();

    for number in 1..=50 {
        rows.push(Box::new(Text::new(format!("item {number}"))));
    }

    LayerWindow::new().width(300.0).height(400.0).child(
        Rectangle::new()
            .width(300.0)
            .height(400.0)
            .fill("#ffffff")
            .child(ScrollArea::new("items", Column::new(rows))),
    )
}
```

### Как работает прокрутка

- `ScrollArea` по умолчанию имеет размер `Parent`, поэтому занимает всё место, которое даёт родитель. Здесь — 300 на 400 пикселей.
- Его ребёнок, столбец, высотой со все 50 строк. Показывается только та часть, которая помещается в область.
- Представление перестраивается каждый кадр, поэтому область не может сама помнить, насколько прокручена. Amane хранит позицию под именем, переданным в `new`, здесь `"items"`. У каждой области должно быть своё имя. Две области с одинаковым именем прокручиваются вместе.

> **Уточнение.** `ScrollArea` не рисует полосу прокрутки. Это только область с обработчиком колеса; индикатор нужно рисовать самостоятельно, если он нужен.
>
> Один шаг колеса равен 15 пикселям (`PIXELS_PER_LINE`), а прокрутка только вертикальная. Горизонтальная составляющая `Scroll` игнорируется.

### Параметры

```rust
ScrollArea::new("apps", Column::new(rows))
    .width(300.0)
    .height(Parent)
```

`width` и `height` по умолчанию `Parent`.

### Скруглённые углы

Поместите область в скруглённый прямоугольник с `clip`, чтобы строки обрезались по дуге:

```rust
Rectangle::new()
    .width(300.0)
    .height(400.0)
    .radius(24.0)
    .fill(Color::WHITE)
    .clip()
    .child(ScrollArea::new("items", Column::new(rows)))
```

### Строки, принимающие ввод

Строки внутри области принимают клики как обычно. Строки, прокрученные за пределы видимой части, кликнуть нельзя.

Строка со своим `on_scroll`, например регулятор громкости, забирает прокрутку, пока указатель над ней, и область не двигается.

> **Уточнение.** Если ребёнок области сам имеет размер `Parent` по высоте, он совпадёт с высотой области, и прокручивать будет нечего. Для списков используйте `Column`, который измеряет высоту по строкам, или задавайте ребёнку фиксированную высоту.

## Canvas и фигуры

`Canvas` рисует формы, которые не умеет прямоугольник: кольца прогресса, шкалы, графики и собственные иконки.

### Кольцо прогресса

Кольцо на 70%:

```rust
use amane::{App, Arc, Canvas, Cap, LayerWindow, Shape, shapes};

fn main() {
    App::new().window(view).run();
}

fn view() -> LayerWindow {
    LayerWindow::new().width(120.0).height(120.0).child(ring(0.7))
}

fn ring(value: f32) -> Canvas {
    Canvas::new().width(120.0).height(120.0).shapes(shapes![
        Arc::new().stroke(10.0, "#45475a"),
        Arc::new().sweep(360.0 * value).stroke(10.0, "#89b4fa").cap(Cap::Round),
    ])
}
```

### Координаты и порядок отрисовки

- `Canvas` — виджет с размером, как прямоугольник. Внутри фигуры размещаются в собственных координатах холста: `(0, 0)` — левый верхний угол, `x` и `y` растут вправо и вниз.
- `shapes!` создаёт список фигур, как `children!` для виджетов. Поздние фигуры рисуются поверх ранних, поэтому синяя дуга лежит на серой дорожке.
- `Arc` без центра и радиуса находится в середине холста, максимального размера, и отступает внутрь на половину толщины линии, чтобы линия осталась внутри.
- `stroke`, `fill`, `cap` и `opacity` приходят из трейта `Shape`, поэтому `Shape` должен быть в `use`, иначе Rust не найдёт методы.

### Фигуры

| Фигура | Builder | По умолчанию |
|---|---|---|
| `Circle` | `.center(x, y)`, `.radius(r)` | центр холста, максимальный размер |
| `Arc` | `.center(x, y)`, `.radius(r)`, `.start(degrees)`, `.sweep(degrees)` | центр, максимальный размер, полный оборот |
| `Line` | `.from(x, y)`, `.to(x, y)` | от `(0, 0)` до `(0, 0)` |
| `Path` | `.move_to`, `.line_to`, `.quad_to`, `.cubic_to`, `.arc`, `.close` | пустой |

Углы `Arc` задаются в градусах. `0` направлен вверх, углы растут по часовой стрелке. Отрицательный `sweep` идёт против часовой. `Path::arc` использует те же углы.

### Заливка, обводка и окончания

У каждой фигуры одни и те же четыре метода:

```rust
.fill("#89b4fa")          // заливает внутренность
.stroke(4.0, "#cdd6f4")   // рисует контур толщиной 4 пикселя
.cap(Cap::Round)          // как выглядят открытые концы: Butt (по умолчанию), Round или Square
.opacity(0.5)
```

Новая фигура ничего не рисует, пока не получит `fill` или `stroke`. Можно задать оба.

### Пути и графики

`Path` — это перо, которое вы перемещаете. Каждый вызов добавляет к одному и тому же пути:

```rust
Path::new()
    .move_to(10.0, 50.0)                      // поднять перо и поставить здесь
    .line_to(50.0, 10.0)                      // прямая
    .quad_to(70.0, 0.0, 90.0, 10.0)           // кривая с одной опорной точкой
    .cubic_to(100.0, 30.0, 100.0, 70.0, 90.0, 90.0)  // кривая с двумя
    .close()                                  // прямая назад к последнему move_to
    .stroke(2.0, "#cdd6f4")
```

Пути удобны для графиков. Строьте их в цикле:

```rust
use amane::{App, Canvas, Cap, LayerWindow, Path, Shape, shapes};

fn main() {
    App::new().window(view).run();
}

fn view() -> LayerWindow {
    let history = [0.2, 0.5, 0.4, 0.8, 0.6, 0.9, 0.3];

    LayerWindow::new().width(200.0).height(60.0).child(graph(&history))
}

fn graph(history: &[f32]) -> Canvas {
    let width = 200.0;
    let height = 60.0;

    let step = width / (history.len() - 1) as f32;

    let mut line = Path::new().move_to(0.0, height * (1.0 - history[0]));

    for (index, value) in history.iter().enumerate().skip(1) {
        line = line.line_to(index as f32 * step, height * (1.0 - value));
    }

    Canvas::new()
        .width(width)
        .height(height)
        .shapes(shapes![line.stroke(2.0, "#a6e3a1").cap(Cap::Round)])
}
```

`y` растёт вниз, поэтому значение 1 рисуется в `y = 0`, наверху.

### Пример: шкала

Полукруг со стрелкой:

```rust
use amane::{App, Arc, Canvas, Cap, Circle, LayerWindow, Line, Shape, shapes};

fn main() {
    App::new().window(view).run();
}

fn view() -> LayerWindow {
    LayerWindow::new().width(120.0).height(80.0).child(gauge(0.4))
}

fn gauge(value: f32) -> Canvas {
    let angle = f32::to_radians(-90.0 + 180.0 * value);

    let needle_x = 60.0 + f32::sin(angle) * 36.0;
    let needle_y = 70.0 - f32::cos(angle) * 36.0;

    Canvas::new().width(120.0).height(80.0).shapes(shapes![
        Arc::new()
            .center(60.0, 70.0)
            .radius(48.0)
            .start(-90.0)
            .sweep(180.0)
            .stroke(8.0, "#45475a")
            .cap(Cap::Round),
        Arc::new()
            .center(60.0, 70.0)
            .radius(48.0)
            .start(-90.0)
            .sweep(180.0 * value)
            .stroke(8.0, "#f9e2af")
            .cap(Cap::Round),
        Line::new().from(60.0, 70.0).to(needle_x, needle_y).stroke(3.0, "#cdd6f4").cap(Cap::Round),
        Circle::new().center(60.0, 70.0).radius(6.0).fill("#cdd6f4"),
    ])
}
```

### Когда использовать Canvas

- Для прямоугольников, таблеток, кругов и всего с тенью используйте `Rectangle`: он проще, может содержать детей и принимать ввод.
- Для дуг, линий, кривых и графиков — `Canvas`.

`Canvas` не может содержать детей и не принимает ввод сам по себе. Чтобы сделать его кликабельным, поместите в прямоугольник с обработчиком:

```rust
use amane::{App, Button, Canvas, LayerWindow, Rectangle};

fn main() {
    App::new().window(view).run();
}

fn view() -> LayerWindow {
    LayerWindow::new().width(120.0).height(120.0).child(
        Rectangle::new()
            .width(120.0)
            .height(120.0)
            .on_click(|_: Button| println!("gauge clicked"))
            .child(Canvas::new().width(120.0).height(120.0)),
    )
}
```

## Изображения

Изображения рисуются как заливка прямоугольника. В этой главе: вписывание, загрузка и экономия памяти для больших картинок.

### Заливка изображением

```rust
use amane::{App, Image, LayerWindow, Rectangle};

fn main() {
    App::new().window(view).run();
}

fn view() -> LayerWindow {
    LayerWindow::new().width(300.0).height(200.0).child(
        Rectangle::new()
            .width(300.0)
            .height(200.0)
            .radius(16.0)
            .fill(Image::cover("/usr/share/backgrounds/default.png")),
    )
}
```

Изображение заполняет прямоугольник, следует его скруглениям и работает с `border`, `shadow` и `opacity`, как любая другая заливка.

### Вписывание

| Режим | Эффект |
|---|---|
| `Image::cover(path)` | заполняет весь прямоугольник, обрезая выходящее за края |
| `Image::contain(path)` | показывает изображение целиком, оставляя остальное пустым |
| `Image::stretch(path)` | заполняет прямоугольник точно, растягивая или сжимая |

`cover` подходит для обоев и обложек альбомов. `contain` — для иконок.

### Форматы и пути

- PNG и JPEG определяются по содержимому, независимо от имени файла. SVG определяется по расширению `.svg` (без учёта регистра).
- Используйте абсолютные пути. Относительный путь считается от папки, из которой запущена оболочка, а это зависит от способа запуска. `~` не раскрывается.
- WebP, GIF, AVIF и другие форматы не поддерживаются. Для них сконвертируйте файл заранее.

### Как загружаются изображения

Декодирование большой картинки занимает достаточно времени, чтобы пропустить кадры, поэтому Amane декодирует в отдельном потоке:

1. При первом запросе файла прямоугольник рисуется без изображения, а декодирование начинается.
2. Когда декодирование завершается, окна, ожидающие это изображение, перерисовываются уже с ним.
3. Дальше декодированное изображение хранится в памяти по пути и появляется мгновенно.

Файл, который не удалось прочитать или декодировать, никогда не появится и не уронит оболочку.

Поскольку изображения кэшируются по пути, изменение файла на диске не меняет то, что показывается. Чтобы показать новые обои, используйте новый путь.

> **Уточнение.** Ключ кэша — это путь, размер `thumbnail` и радиус `blurred`, а не только путь. Поэтому один файл в разных вариантах (полный, уменьшенный, размытый) хранится отдельно. Полноразмерная копия освобождается, когда её больше не рисует ни одно окно; уменьшенные копии остаются.

Чтобы показать заглушку, пока изображение грузится, спросите, готово ли оно:

```rust
// плееры дают ссылку file://, а Image хочет обычный путь
let art = media.art_url().strip_prefix("file://").unwrap_or("");

let cover = if Image::loaded(art) {
    Rectangle::new().width(64.0).height(64.0).fill(Image::cover(art))
} else {
    Rectangle::new().width(64.0).height(64.0).fill("#313244")
};
```

`Image::loaded` также запускает декодирование, если никто ещё не просил изображение.

> **Исправление.** `Image::loaded(path)` проверяет только вариант полного размера без `thumbnail` и без `blurred`. Если вы рисуете `Image::cover(path).thumbnail(64, 64).blurred(8)`, `loaded(path)` может вернуть `true`, хотя нужный уменьшенный вариант ещё не готов, или наоборот. Для точной проверки используйте отдельный флаг в сервисе или заранее подготовьте уменьшенную копию.

### Миниатюры

Обои 4K, показанные как превью 200 пикселей, всё равно держат в памяти все 8 миллионов пикселей. `thumbnail` хранит маленькую копию:

```rust
Image::cover(path).thumbnail(200, 120)
```

Копия ровно настолько велика, чтобы покрыть 200 на 120 пикселей. Полноразмерное изображение выбрасывается сразу после уменьшения. Используйте для выбора обоев, сеток иконок и всего, где показывается много картинок сразу.

### Размытые фоны

```rust
Image::cover(wallpaper).thumbnail(64, 36).blurred(4)
```

`blurred` размывает декодированную копию один раз при загрузке, поэтому не стоит ничего на каждом кадре. Размытие крошечной миниатюры и растягивание её на весь экран — дешёвый способ получить гладкий матовый фон, например для экрана блокировки.

Радиус считается в пикселях самой копии, поэтому на маленькой миниатюре небольшие числа уже дают сильное размытие.

### Иконки приложений

Сервис `Apps` сам находит файл иконки каждой программы:

```rust
let icon = Rectangle::new().width(24.0).height(24.0);

let icon = match app.icon_path() {
    Some(path) => icon.fill(Image::contain(path)),
    None => icon,
};
```

## Шейдеры

Шейдер — небольшая программа, которая выполняется на GPU и вычисляет цвет каждого пикселя прямоугольника. Используйте его для эффектов, недоступных встроенной заливке: анимированные фоны, свечение, шум и собственные градиенты.

### Анимированный шейдер

`~/.config/amane/waves.wgsl`:

```wgsl
@fragment
fn main(@location(0) uv: vec2<f32>) -> @location(0) vec4<f32> {
    let wave = sin(uv.x * 12.0 + time * 2.0) * 0.5 + 0.5;

    return vec4<f32>(uv.x, wave, 1.0 - uv.y, 1.0);
}
```

`main.rs`:

```rust
use amane::{App, LayerWindow, Rectangle};

fn main() {
    App::new().window(view).run();
}

fn view() -> LayerWindow {
    LayerWindow::new().width(200.0).height(200.0).child(
        Rectangle::new()
            .width(200.0)
            .height(200.0)
            .radius(24.0)
            .shader("/home/you/.config/amane/waves.wgsl"),
    )
}
```

Прямоугольник показывает движущиеся цветные волны, обрезанные по скруглённым углам.

### Входы шейдера

GPU выполняет `main` один раз для каждого пикселя прямоугольника, все одновременно. Каждый запуск получает позицию пикселя и возвращает его цвет. Amane передаёт каждому шейдеру:

| Вход | Тип | Значение |
|---|---|---|
| `uv` | `vec2<f32>` | позиция пикселя: `(0, 0)` — левый верхний угол, `(1, 1)` — правый нижний |
| `size` | `vec2<f32>` | размер прямоугольника в пикселях |
| `time` | `f32` | секунды с момента отрисовки первого шейдера |
| `values` | `array<vec4<f32>, 16>` | числа из Rust |

Возвращаемый цвет — красный, зелёный, синий и альфа, каждый от 0 до 1.

Шейдер рисуется поверх заливки прямоугольника, внутри его формы. Скругление, рамка, прозрачность и трансформации прямоугольника продолжают действовать.

> **Уточнение.** Порядок отрисовки: заливка → шейдер → внутренняя тень → рамка → ребёнок. Поэтому рамка видна поверх шейдера, а ребёнок — поверх всего.

### Анимированные шейдеры и кадры

Amane проверяет, упоминает ли исходник шейдера слово `time`. Если да, окно непрерывно рисует новые кадры, пока шейдер на экране, и анимация работает. Если нет, шейдер рисуется один раз и перерисовывается только при других изменениях.

Любое `time` считается, даже в комментарии. Не упоминайте это слово в шейдерах, которые не анимируются, чтобы не занимать GPU.

> **Уточнение.** Проверка идёт по целому слову с границами: `time` в комментарии считается, а `times` или `lifetime` — нет. Это эвристика, а не анализ кода.

### Передача значений из Rust

`shader_values` передаёт до 16 строк по 4 числа из представления в шейдер как `values`. Непереданные строки равны 0.

```rust
Rectangle::new()
    .width(420.0)
    .height(200.0)
    .shader("/home/you/.config/amane/spots.wgsl")
    .shader_values(vec![[2.0, 0.0, 0.0, 0.0], [60.0, 100.0, 30.0, 0.0], [200.0, 80.0, 50.0, 0.0]])
```

```wgsl
// values[0].x — количество пятен, далее по строке на пятно: x, y, радиус
@fragment
fn main(@location(0) uv: vec2<f32>) -> @location(0) vec4<f32> {
    let point = uv * size;

    let count = u32(values[0].x);

    var light = 0.0;

    for (var index = 1u; index <= count; index++) {
        let spot = values[index];

        let distance = length(point - spot.xy);

        light = max(light, 1.0 - smoothstep(spot.z - 1.0, spot.z + 1.0, distance));
    }

    return vec4<f32>(0.54, 0.71, 0.98, light);
}
```

Значения приходят из представления, поэтому могут быть из сервиса или `Animation`: уровень звука, позиция наведения и т. п. Больше 16 строк — паника.

### GLSL

Файлы с расширением `.glsl` или `.frag` читаются как GLSL. Amane сам добавляет строку `#version` и входы. Результат записывается в `color`:

```glsl
void main() {
    vec2 pixel = uv * size;
    vec2 center = size / 2.0;

    float rings = sin(distance(pixel, center) * 0.15 - time * 3.0) * 0.5 + 0.5;

    color = vec4(rings, 0.3, 1.0 - rings, 1.0);
}
```

`values` доступен и в GLSL как `vec4 values[16]`.

Любое другое расширение читается как WGSL.

### Ограничения

- **Точка входа должна называться `main`.**
- **Отсутствующий файл шейдера останавливает оболочку.** Шейдер загружается при первой отрисовке; если файл не читается, оболочка завершается с ошибкой. Шейдер, который не компилируется, оболочку не останавливает: в терминал печатается `amane: gpu error: ...`, а эффект рисуется неправильно. Тестируйте новые шейдеры через `amane dev`, где этот вывод виден.
- **Файл шейдера читается один раз.** Редактирование во время работы оболочки ничего не меняет. `amane dev` не следит за шейдерами, если они не лежат внутри `src/`, поэтому перезапустите оболочку, чтобы увидеть изменения.
- Используйте абсолютные пути по той же причине, что и для изображений.

# Часть IV. Дополнительные окна

## Несколько окон и мониторов

Оболочка редко состоит из одного окна. В этой главе: несколько слойных окон, окно на каждом мониторе, обычные окна приложений, а также открытие и закрытие окон во время работы.

### Несколько окон

Вызовите `.window` для каждого окна:

```rust
use amane::{App, Full, Horizontal, LayerWindow, Parent, Rectangle, Vertical};

fn main() {
    App::new().window(bar).window(corner).run();
}

fn bar() -> LayerWindow {
    LayerWindow::new()
        .width(Full)
        .height(30.0)
        .anchor_vertical(Vertical::Top)
        .child(Rectangle::new().width(Parent).height(Parent).fill("#1e1e2e"))
}

fn corner() -> LayerWindow {
    LayerWindow::new()
        .width(200.0)
        .height(60.0)
        .anchor_vertical(Vertical::Bottom)
        .anchor_horizontal(Horizontal::Right)
        .child(Rectangle::new().width(Parent).height(Parent).fill("#313244"))
}
```

У каждого окна своё представление, и каждое перерисовывается только из-за сервисов, которые читает именно его представление. Окна, добавленные через `.window`, композитор размещает на том мониторе, который выберет, обычно на мониторе с фокусом.

### Окно на каждом мониторе

Бар должен быть на каждом мониторе, включая подключённые позже:

```rust
use amane::{App, Color, Full, Layer, LayerWindow, Monitor, Parent, Rectangle, Text, Vertical};

fn main() {
    App::new().window_per_monitor(bar).run();
}

fn bar(monitor: &Monitor) -> LayerWindow {
    let label = format!("{} {}x{}", monitor.name, monitor.width, monitor.height);

    LayerWindow::new()
        .width(Full)
        .height(30.0)
        .anchor_vertical(Vertical::Top)
        .layer(Layer::Top)
        .child(
            Rectangle::new()
                .width(Parent)
                .height(Parent)
                .fill(Color::BLUE)
                .child(Text::new(label).color(Color::WHITE)),
        )
}
```

Представление получает `&Monitor` с полями `name` (например, `"DP-1"`), `width` и `height`. Размеры используют те же единицы, что и виджеты, с учётом масштаба композитора и коэффициента приложения. Amane открывает по окну на каждый монитор при старте, открывает новое при подключении монитора и закрывает при отключении.

Монитор можно использовать, чтобы показывать разное на разных экранах:

```rust
if monitor.name == "eDP-1" {
    // экран ноутбука
}
```

> **Уточнение.** `width` и `height` округлены до целых единиц виджетов. Если нужно точное совпадение с краями монитора, используйте `Full`, а не вычисленный размер.

### Обычные окна

Обычное окно — это обычное окно приложения с заголовком, которое композитор размещает и тайлит, как любое другое. Используйте его для панели настроек или чего-то, что пользователь должен двигать:

```rust
use amane::{App, Center, Color, Parent, Rectangle, Text, Window};

fn main() {
    App::new().normal_window("settings", settings).run();
}

fn settings() -> Window {
    Window::new()
        .title("amane settings")
        .size(480.0, 320.0)
        .resizable(true)
        .child(
            Rectangle::new()
                .width(Parent)
                .height(Parent)
                .fill("#313244")
                .align_child(Center, Center)
                .child(Text::new("settings go here").color(Color::WHITE)),
        )
}
```

- `title` по умолчанию `"amane"`.
- `size` — размер при открытии, по умолчанию 640 на 480. Композитор может дать другой размер, и тайловый композитор обычно так и делает.
- `resizable` разрешает пользователю менять размер. **По умолчанию `true`.**
- `on_key` работает так же, как у слойного окна. Обычное окно получает фокус клавиатуры как любое приложение, поэтому `Keyboard` ему не нужен.

> **Исправление.** В оригинале сказано, что `resizable` по умолчанию `false`. В `src/window.rs` значение по умолчанию — `true`.

Имя, здесь `"settings"`, отличает окна друг от друга. Оно используется, чтобы закрыть окно позже.

> **Уточнение.** `title`, `size` и `resizable` читаются один раз при открытии окна. Если представление вернёт другие значения позже, они не применятся к уже открытому окну. Чтобы изменить размер, пользователь должен сделать это сам или окно нужно закрыть и открыть заново.

### Открытие и закрытие окон позже

Окна, переданные в `App`, открываются при старте оболочки. Чтобы открыть окно позже, например по кнопке, вызовите `open_window` с именем и представлением:

```rust
use amane::{App, Full, LayerWindow, Parent, Pointer, Rectangle, Window, close_window, open_window};

fn main() {
    App::new().window(bar).run();
}

fn bar() -> LayerWindow {
    LayerWindow::new().width(Full).height(30.0).child(
        Rectangle::new()
            .width(Parent)
            .height(Parent)
            .fill("#1e1e2e")
            .cursor(Pointer)
            .on_click(|_| open_window("settings", settings)),
    )
}

fn settings() -> Window {
    Window::new().title("settings").child(
        Rectangle::new()
            .width(120.0)
            .height(40.0)
            .fill("#f38ba8")
            .on_click(|_| close_window("settings")),
    )
}
```

- `open_window(name, view)` открывает обычное окно. Если окно с таким именем уже открыто, ничего не делает, поэтому двойной клик не создаст два окна.
- `close_window(name)` закрывает окно. Закрытие неоткрытого окна ничего не делает.
- Пользователь также может закрыть обычное окно через заголовок или горячей клавишей композитора.

Обе функции работают откуда угодно: из обработчиков ввода, IPC-обработчиков или потока сервиса.

`open_window` открывает только обычные окна. Чтобы показать или скрыть слойное окно, например всплывающее или лаунчер, держите его открытым и используйте `.visible(...)`.

> **Уточнение.** `open_window` и `close_window` принимают `fn`-указатели. Замыкания с захватом переменных сюда не подходят.

### Реальный размер окна

Композитор может дать окну не тот размер, который оно просило. Внутри представления `window_size()` возвращает реальный размер окна в единицах виджетов, до коэффициента приложения:

```rust
let (width, height) = window_size();
```

До того как композитор сообщит размер, возвращается `(0.0, 0.0)`; это может произойти в самом первом кадре. У скрытого слойного окна размер тоже `(0.0, 0.0)`.

## Экран блокировки

Amane умеет блокировать сессию экраном блокировки, который вы рисуете сами, и проверять пароль через PAM, как это делает экран входа в систему.

Композитор должен поддерживать протокол **ext-session-lock**. niri, Hyprland и Sway его поддерживают.

### Экран блокировки

```rust
use amane::{
    App, Center, Color, Column, LayerWindow, Lock, Monitor, Parent, Rectangle, Service, Text,
    TextInput, children,
};

fn main() {
    App::new().lock(view).run();
}

fn view(_: &Monitor) -> LayerWindow {
    let lock = Lock::read();

    let status = if lock.checking() {
        "checking..."
    } else if lock.failed() {
        "wrong password"
    } else {
        "locked"
    };

    // композитор сам задаёт размер экрана блокировки, поэтому этот размер не используется
    LayerWindow::new().width(1.0).height(1.0).child(
        Rectangle::new()
            .width(Parent)
            .height(Parent)
            .fill("#1e1e2e")
            .align_child(Center, Center)
            .child(
                Column::new(children![
                    Text::new(status).size(24.0).color(Color::WHITE),
                    Rectangle::new()
                        .width(300.0)
                        .height(40.0)
                        .fill(Color::WHITE)
                        .padding(8.0)
                        .child(
                            TextInput::new("password")
                                .placeholder("password")
                                .password()
                                .focused()
                                .on_submit(|password| Lock::unlock(&password)),
                        ),
                ])
                .gap(12.0),
            ),
    )
}
```

Это создаёт экран блокировки, но пока ничего не блокирует. О том, как заблокировать сессию, — ниже.

### Как работает блокировка

- `App::lock` принимает представление, которое показывается на каждом мониторе, пока сессия заблокирована. Как и `window_per_monitor`, оно получает `&Monitor`.
- Пока сессия заблокирована, композитор показывает только экран блокировки, отправляет все клавиши ему и скрывает все остальные окна. Размер, якоря и слой экрана блокировки игнорируются: он всегда покрывает весь монитор.
- `Lock::unlock(password)` проверяет пароль через PAM (сервис `login`, от вашего пользователя). Это может занять несколько секунд, поэтому выполняется в отдельном потоке. И аутентификация, и проверка аккаунта должны пройти успешно, иначе экран остаётся заблокированным.
- Сервис `Lock` сообщает представлению, что происходит, через `checking()` и `failed()`.

### Блокировка сессии

`Lock::start()` блокирует сессию. Вызывайте откуда угодно: из кнопки, IPC-обработчика или потока сервиса. Повторный вызов, когда сессия уже заблокирована, ничего не делает.

Обычная схема — IPC-обработчик, чтобы блокировка срабатывала по горячей клавише или от idle-демона:

```rust
fn main() {
    App::new()
        .ipc("lock", |_| {
            Lock::start();

            String::from("locked")
        })
        .window(bar)
        .lock(lock_screen)
        .run();
}
```

Затем блокируйте по клавише или из `swayidle` / `hypridle`:

```sh
amane ipc call lock
```

Для niri:

```kdl
binds {
    Mod+Alt+L { spawn "amane" "ipc" "call" "lock"; }
}
```

> **Уточнение.** Если в `App` нет `.lock(...)`, `Lock::start()` не блокирует сессию, а печатает `amane: Lock::start needs a lock screen, see App::lock`. Если композитор не поддерживает `ext-session-lock`, также будет ошибка.

### Интерактивная аутентификация

Для настраиваемой политики или диалога с несколькими ответами запустите аутентификацию из обработчика:

```rust
Lock::authenticate(PamConfig::new("my-shell"))?;
```

Читайте сервис `Pam` в представлении блокировки, чтобы показывать информацию, ошибки и текущий запрос. Отвечайте на каждый запрос через `Pam::respond(prompt.id(), response)`, скрывая ввод, если его вид — `PamMessageKind::Prompt { visible: false }`. Обработчик ответа и типы результатов описаны в главе о PAM.

`Lock::authenticate` аутентифицирует текущего `$USER` и отклоняет конфигурацию с другим пользователем. И аутентификация, и проверка аккаунта должны пройти для этого пользователя, чтобы сессия разблокировалась. Отдельный `Pam::start` сессию не разблокирует.

`Lock::abort()` отменяет попытку блокировки и оставляет сессию заблокированной. Если нативный модуль PAM всё ещё работает, его поток остаётся активным до возврата; дождитесь `Pam::read().active() == false`, прежде чем повторять попытку.

### Справочник `Lock`

| Функция | Значение |
|---|---|
| `Lock::read().checking()` | аутентификация выполняется |
| `Lock::read().failed()` | последняя попытка отклонена или завершилась ошибкой |
| `Lock::start()` | блокирует сессию |
| `Lock::unlock(password)` | проверяет пароль и разблокирует, если он верный |
| `Lock::authenticate(config)` | запускает интерактивную аутентификацию и разблокирует при успехе |
| `Lock::abort()` | отменяет аутентификацию, оставляя сессию заблокированной |

Одновременно выполняется только одна попытка PAM. Вызов `unlock` во время проверки ничего не делает; `authenticate` возвращает `PamError::Busy`. Функция `unlock` передаёт один и тот же пароль на все запросы. Если политика требует разных ответов, используйте интерактивную аутентификацию. Каждая новая блокировка начинается с чистого состояния, без `failed` от прошлой.

> **Уточнение.** `Lock::unlock` игнорирует ошибки PAM: при неверном пароле вы simply увидите `failed() == true`, исключения или возврата ошибки нет. Если нужна причина, используйте `Lock::authenticate` и `Pam`.

### Безопасное тестирование

Заблокированная сессия откроется только с правильным паролем. Если в экране блокировки есть ошибка, например поле не принимает клавиши, вы не сможете вернуться в эту сессию.

Убийство оболочки тоже не поможет. Если программа, заблокировавшая сессию, завершится без разблокировки, композитор оставит сессию заблокированной. Это сделано намеренно: иначе падение экрана блокировки было бы способом его обойти.

Перед реальным использованием нового экрана блокировки:

- сохраните работу в других приложениях;
- переключитесь на другой TTY (`Ctrl+Alt+F3`), войдите там и держите его открытым. Если застряли, вернитесь туда и завершите сессию командой `loginctl terminate-session <id>` (`loginctl list-sessions` покажет id). Это закроет все приложения этой сессии;
- сначала попробуйте неверный пароль, затем верный.

```rust

    .width(Parent)

    .fill(Image::cover("/home/you/Pictures/wall.jpg").thumbnail(64, 36).blurred(4))
```

# Часть V. Встроенные сервисы

Amane включает сервисы для данных, которые обычно показывает бар: батарея, процессор, память, яркость, звук, сеть, Bluetooth, медиаплееры, уведомления, рабочие столы, приложения и цвета обоев. Плюс `Pam` для интерактивной аутентификации.

Все они используются как собственные сервисы: `Service::read()` в представлении, окно обновляется при изменении значения. Первое чтение запускает сервис.

## Обзор

| Сервис | Источник | Как получает данные | Как часто |
|---|---|---|---|
| `Battery` | `/sys/class/power_supply` | опрос | 5 секунд |
| `Cpu` | `/proc/stat` | опрос | 2 секунды |
| `Memory` | `/proc/meminfo` | опрос | 2 секунды |
| `Brightness` | `/sys/class/backlight`, logind | опрос | 500 миллисекунд |
| `Audio` | PulseAudio/PipeWire | события сервера | мгновенно |
| `Network` | NetworkManager (D-Bus) | опрос | 1 секунда |
| `Bluetooth` | BlueZ (D-Bus) | опрос | 2 секунды |
| `Media` | MPRIS (D-Bus) | опрос | 1 секунда |
| `Notifications` | D-Bus | сервер, события | мгновенно |
| `Workspaces` | событийный поток композитора | события | мгновенно |
| `Apps` | `.desktop`-файлы | фоновое сканирование | 30 секунд |
| `Palette` | файл изображения | опрос времени изменения | 500 миллисекунд |
| `Pam` | Linux-PAM | диалог в фоне | по запросу |
| `Lock` | PAM + compositor | по запросу | — |

> **Исправление.** В книге не указан интервал `Brightness`. В `src/services/brightness.rs` он равен 500 миллисекундам. Там же, где книга говорит «опрос», сервис использует обычный `listen` с `interval` и `update`; сервисы с пометкой «события» заменяют `listen` собственным циклом.

## Система: батарея, процессор, память, яркость

### Все четыре сразу

```rust
use amane::{App, Battery, Brightness, Cpu, Full, LayerWindow, Memory, Service, Text};

fn main() {
    App::new().window(view).run();
}

fn view() -> LayerWindow {
    let battery = Battery::read();
    let cpu = Cpu::read();
    let memory = Memory::read();
    let brightness = Brightness::read();

    let label = format!(
        "battery {}%   cpu {}%   memory {}%   brightness {}%",
        battery.percent(),
        cpu.percent(),
        memory.percent(),
        brightness.percent()
    );

    LayerWindow::new().width(Full).height(30.0).child(Text::new(label))
}
```

`Service` должен быть в `use`, потому что `read()` приходит из этого трейта.

### Battery

Читается из ядра (`/sys/class/power_supply`) каждые 5 секунд.

| Функция | Что даёт |
|---|---|
| `present()` | `false`, если батареи нет |
| `percent()` | заряд, 0–100 |
| `charging()` | `true`, пока идёт зарядка |
| `full()` | `true`, когда батарея подключена и не заряжается |

На настольном компьютере `present()` равно `false`, остальное — 0. Скрывайте виджет батареи там:

```rust
if battery.present() {
    // показать батарею
}
```

> **Уточнение.** `full()` соответствует статусу ядра `Full` или `Not charging`. Обычно это «подключена и не заряжается», но при порогах зарядки и особенностях драйвера возможны нюансы. Отдельного метода «питание подключено» в `Battery` нет.

`Battery` ищет первую батарею, которая питает компьютер; батареи мыши и ИБП с `scope = Device` пропускаются.

### CPU

Читается из `/proc/stat` каждые 2 секунды.

| Функция | Что даёт |
|---|---|
| `percent()` | загрузка по всем ядрам, 0–100 |

Загрузка существует только как разница между двумя измерениями. Самое первое значение — среднее с момента загрузки машины, дальше показывается текущая загрузка.

### Memory

Читается из `/proc/meminfo` каждые 2 секунды.

| Функция | Что даёт |
|---|---|
| `percent()` | занятая память, 0–100 |
| `used_kib()` | занятая память в кибибайтах |
| `total_kib()` | вся память в кибибайтах |

«Занятая» — то, что держат программы. Кэш, который ядро может освободить сразу, не считается, как и в выводе `free`.

### Brightness

Читает подсветку экрана из ядра (`/sys/class/backlight`).

| Функция | Что даёт |
|---|---|
| `present()` | `false`, если у монитора нет подсветки (обычная ситуация для внешних мониторов) |
| `percent()` | яркость, 0–100 |
| `Brightness::set(percent)` | задаёт яркость |

`set` идёт через logind, поэтому пользователь, сидящий за этой машиной, может менять подсветку без root и пароля. Значение никогда не опускается ниже 1%: чёрный экран трудно вернуть, если его не видно.

Прокрутка над виджетом меняет яркость:

```rust
use amane::{App, Brightness, LayerWindow, Parent, Rectangle, Scroll, Service, Text};

fn main() {
    App::new().window(view).run();
}

fn view() -> LayerWindow {
    let brightness = Brightness::read();

    LayerWindow::new().width(200.0).height(30.0).child(
        Rectangle::new()
            .width(Parent)
            .height(Parent)
            .on_scroll(scrolled)
            .child(Text::new(format!("brightness {}%", brightness.percent()))),
    )
}

// каждый шаг колеса меняет яркость на 5
fn scrolled(scroll: Scroll) {
    let current = i32::from(Brightness::read().percent());

    let step = if scroll.y < 0.0 { 5 } else { -5 };

    let changed = (current + step).clamp(1, 100);

    Brightness::set(changed as u8);
}
```

`set` выполняется в фоновом потоке, поэтому медленный ответ не замораживает оболочку.

## Audio

`Audio` читает и меняет громкость динамика и микрофона по умолчанию. Он общается с PulseAudio, что покрывает и PipeWire через `pipewire-pulse` — на большинстве дистрибутивов он включён.

`Audio` не опрашивает сервер. Звуковой сервер сам сообщает об изменениях, поэтому бар обновляется сразу после нажатия клавиши громкости.

### Виджет громкости

Прокрутка меняет громкость, клик выключает звук:

```rust
use amane::{App, Audio, Button, LayerWindow, Parent, Rectangle, Scroll, Service, Text};

fn main() {
    App::new().window(view).run();
}

fn view() -> LayerWindow {
    let audio = Audio::read();

    let label = if audio.muted() {
        String::from("muted")
    } else {
        format!("volume {}%", audio.volume())
    };

    LayerWindow::new().width(200.0).height(30.0).child(
        Rectangle::new()
            .width(Parent)
            .height(Parent)
            .on_click(clicked)
            .on_scroll(scrolled)
            .child(Text::new(label)),
    )
}

fn clicked(_: Button) {
    Audio::toggle_mute();
}

// каждый шаг колеса меняет громкость на 5
fn scrolled(scroll: Scroll) {
    let volume = i32::from(Audio::read().volume());

    let step = if scroll.y < 0.0 { 5 } else { -5 };

    let changed = (volume + step).clamp(0, 100);

    Audio::set_volume(changed as u8);
}
```

### Справочник

| Функция | Что даёт или делает |
|---|---|
| `volume()` | громкость динамика, 0–100 |
| `muted()` | `true`, если динамик выключен |
| `microphone_volume()` | громкость микрофона, 0–100 |
| `microphone_muted()` | `true`, если микрофон выключен |
| `Audio::set_volume(volume)` | задаёт громкость динамика, 0–100 |
| `Audio::toggle_mute()` | выключает или включает динамик |
| `Audio::set_microphone_volume(volume)` | задаёт громкость микрофона, 0–100 |
| `Audio::toggle_microphone_mute()` | выключает или включает микрофон |

«Динамик» и «микрофон» означают устройства вывода и ввода по умолчанию. При смене устройства, например при подключении наушников, `Audio` следует за ней.

Функции управления выполняются в фоновом потоке, поэтому медленный звуковой сервер не замораживает оболочку. Новое значение появляется, когда сервер о нём сообщит, обычно сразу.

> **Уточнение.** Значения выше 100 не ошибка: `set_volume` и `set_microphone_volume` молча считают их за 100. Прочитанное `volume()` всегда в пределах 0–100.

## Network

`Network` показывает текущее соединение и список Wi-Fi сетей, умеет подключаться, отключаться и сканировать. Он общается с NetworkManager через D-Bus, поэтому NetworkManager должен быть запущен. Без него всё читается как offline.

Сервис опрашивается раз в секунду, потому что сила Wi-Fi сигнала меняется постоянно, и никто об этом не сообщает. Опрос, который не нашёл изменений, ничего не перерисовывает.

### Метка соединения

```rust
use amane::{App, Full, LayerWindow, Link, Network, Service, Text};

fn main() {
    App::new().window(view).run();
}

fn view() -> LayerWindow {
    let network = Network::read();

    let label = match network.link() {
        Link::Offline => String::from("offline"),
        Link::Wired => String::from("wired"),
        Link::Wifi => format!("{}  {}%", network.ssid(), network.strength()),
        Link::Other => String::from("connected"),
    };

    LayerWindow::new().width(Full).height(30.0).child(Text::new(label))
}
```

`Link::Other` охватывает соединения, которые не проводные и не Wi-Fi: VPN, USB-модем телефона и подобное.

### Чтение соединения

| Функция | Что даёт |
|---|---|
| `connected()` | `true`, если есть любое соединение |
| `link()` | `Link::Offline`, `Wired`, `Wifi` или `Other` |
| `ssid()` | имя Wi-Fi сети, пустое на проводном соединении |
| `strength()` | сигнал Wi-Fi, 0–100; 0 на проводном |
| `wifi_enabled()` | `false`, если радиомодуль Wi-Fi выключен |
| `connecting()` | `true`, пока идёт подключение |
| `access_points()` | сети Wi-Fi в зоне действия; пусто, если нет Wi-Fi устройства или радио выключено |

Каждый `AccessPoint` в `access_points()` имеет:

| Функция | Что даёт |
|---|---|
| `ssid()` | имя сети |
| `strength()` | сигнал, 0–100 |
| `secured()` | `true`, если нужен пароль |
| `active()` | `true` для сети, в которой вы сейчас |
| `saved()` | `true`, если у NetworkManager уже есть профиль этой сети |

### Подключение и отключение

| Функция | Что делает |
|---|---|
| `Network::scan()` | ищет сети. Новые появятся в `access_points()` через несколько секунд. |
| `Network::connect(ssid, password)` | подключается к сети |
| `Network::disconnect()` | выходит из текущей Wi-Fi сети |
| `Network::set_wifi(enabled)` | включает или выключает радиомодуль Wi-Fi |

Все они выполняются в фоновом потоке и возвращаются сразу. Результат появится при следующем опросе.

`connect` принимает пароль как `Option`:

- для **сохранённой** сети передайте `None`: NetworkManager уже хранит пароль;
- для **новой защищённой** сети передайте `Some(password)`: NetworkManager создаст новый профиль с ним, и в следующий раз сеть уже будет сохранённой;
- для **новой открытой** сети передайте `None`.

> **Уточнение.** Если профиль уже сохранён, переданный пароль полностью игнорируется: соединение активируется с сохранёнными настройками. Чтобы сменить сохранённый пароль, удалите профиль средствами NetworkManager (`nmcli connection delete <ssid>`), после чего `connect` создаст его заново.

### Список сетей

```rust
use amane::{App, Column, LayerWindow, Network, Parent, Rectangle, Service, Text, Widget};

fn main() {
    App::new().window(view).run();
}

fn view() -> LayerWindow {
    let network = Network::read();

    let mut rows: Vec<Box<dyn Widget>> = Vec::new();

    for access_point in network.access_points() {
        let mark = if access_point.active() { "* " } else { "" };

        let label = format!("{mark}{}  {}%", access_point.ssid(), access_point.strength());

        let ssid = String::from(access_point.ssid());

        rows.push(Box::new(
            Rectangle::new()
                .width(Parent)
                .height(30.0)
                .on_click(move |_| Network::connect(&ssid, None))
                .child(Text::new(label)),
        ));
    }

    LayerWindow::new().width(300.0).height(400.0).child(Column::new(rows).width(Parent))
}
```

`ssid` копируется в `String` до замыкания, потому что замыкание живёт дольше, чем `network`.

Для новых защищённых сетей совместите это с парольным `TextInput`.

## Bluetooth

`Bluetooth` показывает адаптер и его устройства, умеет включать адаптер, сканировать, спаривать, подключать и забывать устройства. Он общается с BlueZ через D-Bus, поэтому служба `bluetooth` должна быть запущена.

Опрос идёт каждые 2 секунды.

### Список устройств

```rust
use amane::{App, Bluetooth, BluetoothDevice, Column, LayerWindow, Parent, Rectangle, Service, Text, Widget};

fn main() {
    Bluetooth::start_scan();

    App::new().window(view).run();
}

fn view() -> LayerWindow {
    let bluetooth = Bluetooth::read();

    let mut rows: Vec<Box<dyn Widget>> = Vec::new();

    for device in bluetooth.devices() {
        rows.push(Box::new(device_row(device)));
    }

    LayerWindow::new().width(360.0).height(400.0).child(Column::new(rows))
}

fn device_row(device: &BluetoothDevice) -> Rectangle {
    let state = if device.connected() {
        "connected"
    } else if device.paired() {
        "paired"
    } else {
        "new"
    };

    let path = String::from(device.path());
    let connected = device.connected();
    let paired = device.paired();

    Rectangle::new()
        .width(Parent)
        .height(30.0)
        .on_click(move |_| {
            if connected {
                Bluetooth::disconnect(&path);
            } else if paired {
                Bluetooth::connect(&path);
            } else {
                Bluetooth::pair(&path);
            }
        })
        .child(Text::new(format!("{}  {state}", device.name())))
}
```

### Чтение состояния

| Функция | Что даёт |
|---|---|
| `available()` | `false`, если нет адаптера или BlueZ не запущен |
| `powered()` | `true`, если адаптер включён |
| `scanning()` | `true`, пока идёт поиск новых устройств |
| `devices()` | известные и найденные устройства: сначала подключённые, затем спаренные, затем по имени |

Каждый `BluetoothDevice` имеет:

| Функция | Что даёт |
|---|---|
| `name()` | имя, например `"WH-1000XM4"` |
| `address()` | аппаратный адрес |
| `path()` | путь BlueZ, который принимают функции управления |
| `icon()` | имя иконки BlueZ для типа устройства, например `"audio-headphones"` |
| `paired()` | `true`, если устройство спарено |
| `connected()` | `true`, пока устройство подключено |
| `battery()` | заряд устройства, 0–100, если устройство его сообщает; иначе `None` |

### Управление

| Функция | Что делает |
|---|---|
| `Bluetooth::set_powered(on)` | включает или выключает адаптер |
| `Bluetooth::start_scan()` | начинает поиск новых устройств. Они появляются в `devices()` по мере обнаружения. |
| `Bluetooth::stop_scan()` | останавливает поиск |
| `Bluetooth::pair(path)` | спаривает устройство, затем подключает, как другие Bluetooth-меню |
| `Bluetooth::connect(path)` | подключает спаренное устройство |
| `Bluetooth::disconnect(path)` | отключает устройство |
| `Bluetooth::forget(path)` | убирает спаривание и удаляет устройство. Оно вернётся только после нового сканирования. |

Все они выполняются в фоновом потоке и возвращаются сразу. Результат появится при следующем опросе.

`pair` работает только с устройствами, которые спариваются без кода: наушники, мыши и большинство колонок. Устройства, которые просят подтверждение или ввод кода, например телефоны и некоторые клавиатуры, пока нельзя спарить из Amane. Спарьте их один раз через `bluetoothctl`, после чего `connect` заработает.

## Медиаплееры

`Media` показывает, что играет, и управляет воспроизведением в любом плеере с поддержкой MPRIS: Spotify, mpv, вкладках Firefox и Chromium, VLC и большинстве остальных.

Опрос идёт раз в секунду, потому что плееры не сообщают позицию трека постоянно.

### Виджет now playing

```rust
use amane::{App, Button, Full, LayerWindow, Media, Parent, Rectangle, Row, Service, Text, children};

fn main() {
    App::new().window(view).run();
}

fn view() -> LayerWindow {
    let media = Media::read();

    let symbol = if media.playing() { "pause" } else { "play" };

    let seconds = media.position().as_secs();
    let total = media.length().as_secs();

    let label = format!(
        "{} - {}  {}:{:02} / {}:{:02}",
        media.artist(),
        media.title(),
        seconds / 60,
        seconds % 60,
        total / 60,
        total % 60,
    );

    LayerWindow::new().width(Full).height(30.0).child(Row::new(children![
        button("prev", |_| Media::previous()),
        button(symbol, |_| Media::play_pause()),
        button("next", |_| Media::next()),
        Rectangle::new().width(Parent).height(Parent).child(Text::new(label)),
    ]))
}

fn button(label: &str, clicked: fn(Button)) -> Rectangle {
    Rectangle::new()
        .width(60.0)
        .height(Parent)
        .on_click(clicked)
        .child(Text::new(label))
}
```

### Активный плеер

Когда открыто несколько плееров, функции самого `Media` показывают и управляют одним из них — **активным**:

1. тем, который играет;
2. либо тем, который показывался последним;
3. либо первым.

| Функция | Что даёт или делает |
|---|---|
| `title()` | название трека, пустое, если плеер не открыт |
| `artist()` | исполнитель трека |
| `art_url()` | ссылка на обложку, обычно `file://...` или `https://...` |
| `playing()` | `true`, пока идёт воспроизведение |
| `position()` | позиция в треке, `Duration` |
| `length()` | длительность трека, `Duration` |
| `Media::play_pause()` | переключает воспроизведение и паузу |
| `Media::next()` | следующий трек |
| `Media::previous()` | предыдущий трек |

`Duration` — это `std::time::Duration`. Используйте `.as_secs()`, чтобы получить целые секунды.

Чтобы показать обложку, отбросьте `file://` из `art_url()` и используйте путь как изображение. Ссылки `https://` показать нельзя: `Image` не скачивает файлы.

> **Уточнение.** Если играющий плеер уже был активным и его поставили на паузу, `Media` не переключается на другой плеер: активным остаётся тот же, пока не появится новый играющий. Так бар не «прыгает» при паузе.

### Все плееры

`players()` перечисляет все открытые плееры в одном и том же порядке при каждом опросе, а `active()` даёт активный или `None`, если плееров нет. У каждого `MediaPlayer` те же функции, что выше, плюс `identity()` (отображаемое имя, например `"Spotify"`), `name()` (имя в D-Bus) и собственные `play_pause()`, `next()`, `previous()`:

```rust
use amane::{App, Column, Full, LayerWindow, Media, MediaPlayer, Parent, Rectangle, Service, Text, Widget};

fn main() {
    App::new().window(view).run();
}

fn view() -> LayerWindow {
    let media = Media::read();

    let mut rows: Vec<Box<dyn Widget>> = Vec::new();

    for player in media.players() {
        rows.push(Box::new(player_row(player)));
    }

    LayerWindow::new().width(Full).height(90.0).child(Column::new(rows))
}

fn player_row(player: &MediaPlayer) -> Rectangle {
    let label = format!("{}: {} - {}", player.identity(), player.artist(), player.title());

    // замыкание держит свою копию, поэтому продолжает управлять этим плеером
    let target = player.clone();

    Rectangle::new()
        .width(Parent)
        .height(30.0)
        .on_click(move |_| target.play_pause())
        .child(Text::new(label))
}
```

Функции управления выполняются в фоновом потоке и возвращаются сразу.

## Уведомления

`Notifications` делает вашу оболочку сервером уведомлений. Программы отправляют уведомления в Amane так же, как отправляли бы их mako или dunst, а вы решаете, как их показывать.

### Перед началом

Одновременно может работать только один сервер уведомлений. Остановите текущий (mako, dunst, swaync или функцию уведомлений в другом баре) перед запуском оболочки. Если другой демон уже работает, `running()` вернёт `false`, и Amane ничего не получит.

Amane становится демоном при первом чтении `Notifications`, поэтому читайте его в представлении, которое открыто при старте оболочки.

### Список уведомлений

```rust
use amane::{
    App, Column, Horizontal, Layer, LayerWindow, Notification, Notifications, Parent, Rectangle,
    Service, Text, Urgency, Vertical, Widget,
};

fn main() {
    App::new().window(view).run();
}

fn view() -> LayerWindow {
    let notifications = Notifications::read();

    let mut cards: Vec<Box<dyn Widget>> = Vec::new();

    for notification in notifications.list() {
        cards.push(Box::new(card(notification)));
    }

    LayerWindow::new()
        .width(400.0)
        .height(600.0)
        .anchor_vertical(Vertical::Top)
        .anchor_horizontal(Horizontal::Right)
        .layer(Layer::Overlay)
        .visible(!notifications.list().is_empty())
        .child(Column::new(cards).gap(8.0))
}

// клик по уведомлению выполняет действие по умолчанию или закрывает его
fn card(notification: &Notification) -> Rectangle {
    let fill = match notification.urgency() {
        Urgency::Critical => "#f38ba8",
        _ => "#313244",
    };

    let id = notification.id();

    let label = format!("{}: {}", notification.summary(), notification.body());

    Rectangle::new()
        .width(Parent)
        .height(60.0)
        .radius(12.0)
        .fill(fill)
        .padding(12.0)
        .on_click(move |_| Notifications::click(id))
        .child(Text::new(label).elide())
}
```

Окно скрывает себя, пока уведомлений нет, поэтому пустое место не перехватывает клики у окон под ним.

Проверьте:

```sh
notify-send "hello" "from amane"
```

### Чтение уведомлений

`list()` даёт все уведомления, от старых к новым. Каждый `Notification` имеет:

| Функция | Что даёт |
|---|---|
| `id()` | номер, который принимают функции управления |
| `app_name()` | имя отправившей программы |
| `summary()` | однострочный заголовок |
| `body()` | текст; может быть пустым и может содержать простую разметку вроде `<b>` |
| `icon()` | имя иконки вроде `"firefox"`, путь к файлу или пустую строку |
| `image()` | картинку для уведомления, например аватар: путь к файлу, ссылку `file://` или пустую строку |
| `urgency()` | `Urgency::Low`, `Normal` или `Critical` |
| `actions()` | кнопки, запрошенные отправителем, по порядку |
| `has_default_action()` | делает ли что-то клик по самому уведомлению |
| `received()` | когда оно пришло или когда отправитель заменил его, `SystemTime` |

У каждого `Action` есть `key()` — его передают в `invoke`, и `label()` — текст для кнопки.

> **Исправление.** Утверждение «`body()` может содержать разметку вроде `<b>`» относится к протоколу D-Bus, но не к отрисовке Amane: `Text` не разбирает HTML и не поддерживает rich text. Теги будут нарисованы буквально. Если нужен чистый текст, уберите их самостоятельно. Не интерпретируйте тело уведомления как доверенный HTML.

### Клик, закрытие и действия

| Функция | Что делает |
|---|---|
| `Notifications::click(id)` | выполняет действие по умолчанию или закрывает уведомление, если действия нет. Вызывайте при клике по самому уведомлению. |
| `Notifications::invoke(id, key)` | выполняет одно из действий. Для кнопок действий. |
| `Notifications::dismiss(id)` | закрывает уведомление |
| `Notifications::clear()` | закрывает все |

После выполнения действия уведомление закрывается, если отправитель не попросил оставить его.

### Кнопки действий

```rust
for action in notification.actions() {
    let id = notification.id();
    let key = String::from(action.key());

    buttons.push(Box::new(
        Rectangle::new()
            .width(100.0)
            .height(30.0)
            .on_click(move |_| Notifications::invoke(id, &key))
            .child(Text::new(action.label())),
    ));
}
```

Проверьте:

```sh
notify-send -A yes=Yes -A no=No "question" "pick one"
```

### Тайм-ауты

Уведомления остаются, пока их не закроют. Amane игнорирует тайм-аут, который просит отправитель.

Чтобы скрывать всплывающие карточки через несколько секунд, сравнивайте `received()` с текущим временем в сервисе с опросом раз в секунду и показывайте во всплывающем окне только недавние. Полный список храните для центра уведомлений.

> **Уточнение.** `running()` становится `true` только после того, как Amane успешно займёт имя `org.freedesktop.Notifications`. Первые кадры после старта могут дать `false`. Если имя занято, сервис остаётся доступным, но `running()` навсегда `false`.

## Рабочие столы

`Workspaces` перечисляет рабочие столы композитора и умеет переключаться между ними. Поддерживаются **niri**, **Hyprland**, **Sway** и **Mango (MangoWC)**. На других композиторах список остаётся пустым.

Сервис не опрашивает: он следует событийному потоку композитора, поэтому бар обновляется в момент переключения.

На Mango каждый тег — рабочий стол. Несколько тегов могут быть активны на одном мониторе одновременно, и у каждого активного тега на мониторе с фокусом `focused() == true`. Теги сообщают номер, монитор, срочность и число окон; имена тегов Mango через IPC не передаются. `Workspaces::focus(id)` выбирает тег на его мониторе. Mango определяется по переменной `MANGO_INSTANCE_SIGNATURE` и опрашивается напрямую через IPC-сокет, поэтому `mmsg` не требуется.

### Кнопки рабочих столов

```rust
use amane::{App, Color, Full, LayerWindow, Parent, Rectangle, Row, Service, Text, Widget, Workspace, Workspaces};

fn main() {
    App::new().window(view).run();
}

fn view() -> LayerWindow {
    let workspaces = Workspaces::read();

    let mut buttons: Vec<Box<dyn Widget>> = Vec::new();

    for workspace in workspaces.list() {
        buttons.push(Box::new(button(workspace)));
    }

    LayerWindow::new().width(Full).height(30.0).child(Row::new(buttons))
}

fn button(workspace: &Workspace) -> Rectangle {
    let fill = if workspace.focused() {
        "#89b4fa"
    } else if workspace.urgent() {
        "#f38ba8"
    } else {
        "#313244"
    };

    let id = workspace.id();

    Rectangle::new()
        .width(30.0)
        .height(Parent)
        .fill(fill)
        .on_click(move |_| Workspaces::focus(id))
        .child(Text::new(workspace.index().to_string()).color(Color::WHITE))
}
```

### Справочник

`list()` даёт все рабочие столы, отсортированные по монитору, затем по позиции на нём. Каждый `Workspace` имеет:

| Функция | Что даёт |
|---|---|
| `id()` | идентификатор для `Workspaces::focus`: id композитора или id, который Amane назначает паре монитор/тег на Mango; `i64`, потому что у именованных рабочих столов Hyprland id отрицательные |
| `index()` | позицию на своём мониторе, начиная с 1; на Hyprland и Sway — номер рабочего стола (0 для стола только с именем) |
| `name()` | имя или `None`, если имя не задано |
| `output()` | монитор, например `"DP-1"`, или `None` |
| `active()` | `true`, когда стол показан на своём мониторе, даже если фокус на другом мониторе; на Mango активных тегов может быть несколько |
| `focused()` | `true` для стола с общим фокусом; на Mango — для каждого активного тега на мониторе с фокусом |
| `urgent()` | `true`, когда окно просит внимания; на Hyprland всегда `false` |
| `windows()` | сколько окон на столе |

`Workspaces::focus(id)` переключает рабочий стол. Выполняется в фоновом потоке и возвращается сразу.

> **Исправление.** В книге не сказано, что рабочие столы `special`/`special:*` Hyprland (scratchpad) пропускаются и в список не попадают. На Mango теги нумеруются с 1 до 31: нулевая маска означает особый рабочий стол, а не обычный тег. Имена тегов Mango через IPC недоступны, поэтому `name()` всегда `None`.

## Приложения

`Apps` перечисляет установленные программы из `.desktop`-файлов, с именами и иконками. Используйте его для лаунчера.

### Лаунчер

```rust
use amane::{App, Apps, Color, Column, Image, LayerWindow, Pointer, Rectangle, Row, ScrollArea, Service, Text, Widget, children};

fn main() {
    App::new().window(view).run();
}

fn view() -> LayerWindow {
    let apps = Apps::read();

    let mut rows: Vec<Box<dyn Widget>> = Vec::new();

    for app in apps.list() {
        let launched = app.clone();

        let icon = Rectangle::new().width(24.0).height(24.0);

        let icon = match app.icon_path() {
            Some(path) => icon.fill(Image::contain(path)),
            None => icon,
        };

        let row = Rectangle::new()
            .width(300.0)
            .height(32.0)
            .fill("#1e1e2e")
            .cursor(Pointer)
            .on_click(move |_| launched.launch())
            .child(Row::new(children![
                icon,
                Text::new(app.name()).size(16.0).color(Color::WHITE),
            ]));

        rows.push(Box::new(row));
    }

    LayerWindow::new()
        .width(300.0)
        .height(500.0)
        .child(ScrollArea::new("apps", Column::new(rows)))
}
```

`App` (оболочка) и `Apps` (сервис) — разные вещи. `app` в цикле — один `DesktopApp`.

### Справочник

`list()` даёт все программы, отсортированные по имени, без помеченных как скрытые или не показываемые в меню. Каждый `DesktopApp` имеет:

| Функция | Что даёт или делает |
|---|---|
| `name()` | имя, например `"Firefox"` |
| `description()` | комментарий или общее название вроде `"Web Browser"`, либо `None` |
| `exec()` | командную строку без заполнителей вида `%f` |
| `icon()` | имя иконки в теме, например `"firefox"`, или `None` |
| `icon_path()` | файл иконки, PNG, если он есть в теме, или `None` |
| `launch()` | запускает программу, не ожидая её |

### Первая загрузка и повторные сканирования

Поиск иконок обходит все темы иконок в системе и занимает несколько секунд. Поэтому `list()` сначала пуст и заполняется после первого сканирования. Окно само перерисуется, когда это произойдёт.

После этого список сканируется заново каждые 30 секунд, поэтому программы, установленные во время работы оболочки, появляются сами.

### Поиск

Фильтруйте список через `TextInput`:

```rust
let query = search.query.to_lowercase();

for app in apps.list() {
    if !app.name().to_lowercase().contains(&query) {
        continue;
    }

    // добавить строку
}
```

> **Уточнение.** Сканирование читает стандартные каталоги XDG `applications` (`~/.local/share`, `/usr/share` и остальные из `XDG_DATA_DIRS`); файл в более раннем каталоге перекрывает одноимённый в более позднем. Учитываются только `Type=Application` без `Hidden=true` и `NoDisplay=true`.

## Palette

`Palette` извлекает основные цвета изображения, обычно обоев, чтобы цвета оболочки следовали за ними.

### Тематизированный бар

```rust
use amane::{App, Full, LayerWindow, Palette, Parent, Rectangle, Service, Text};

fn main() {
    Palette::write().open("/home/you/Pictures/wall.jpg", 16);

    App::new().window(view).run();
}

fn view() -> LayerWindow {
    let palette = Palette::read();

    LayerWindow::new().width(Full).height(30.0).child(
        Rectangle::new()
            .width(Parent)
            .height(Parent)
            .fill(palette.background())
            .child(Text::new("themed").color(palette.foreground())),
    )
}
```

### Как выбираются и обновляются цвета

- `open(path, count)` читает изображение и выбирает `count` цветов. Изображение читается сразу, поэтому уже первый кадр получает цвета. 16 достаточно для темы всей оболочки.
- `open` меняет `Palette`, поэтому вызывается у `write()`, и все окна, читающие палитру, перерисовываются. Это единственное место, где `write()` уместен вне обработчика ввода: в `main` до запуска оболочки или в IPC-обработчике.
- `Palette` проверяет файл дважды в секунду. Когда изображение меняется или вы вызываете `open` с новым путём, цвета выбираются заново в фоновом потоке, и окна перерисовываются.

Поэтому скрипт обоев, перезаписывающий один и тот же файл, сам перекрашивает оболочку.

### Справочник

| Функция | Что даёт или делает |
|---|---|
| `open(path, count)` | читает изображение и выбирает `count` цветов. Вызывать у `Palette::write()`. |
| `colors()` | все выбранные цвета, самые частые первыми |
| `dominant()` | цвет, которого на изображении больше всего |
| `accent()` | самый яркий цвет, для акцентов и рабочего стола с фокусом |
| `background()` | самый тёмный цвет, чтобы светлый текст всегда читался |
| `foreground()` | цвет, читаемый на `background()`, по возможности подкрашенный изображением |
| `on_accent()` | белый или чёрный, что лучше читается на `accent()` |
| `light()` | `true`, если изображение в целом светлое |

> **Исправление.** Формулировка «до открытия изображения палитра хранит набор цветов по умолчанию» неверна. `colors()` до `open()` возвращает **пустой** список. Значения по умолчанию есть только у отдельных геттеров: `dominant()` и `background()` дают `#11111b`, `accent()` — `#89b4fa`, `light()` — `false`, а `foreground()` и `on_accent()` вычисляются из этих значений. Поэтому `palette.colors()[0]` до `open()` паникует.

> **Уточнение.** Если файл не читается или ещё дописывается, `open` оставляет `colors()` пустым, а геттеры возвращают значения по умолчанию. `Palette` продолжает следить за временем изменения файла и подхватит его, когда он станет целым.

### Смена обоев по горячей клавише

```rust
fn main() {
    App::new()
        .ipc("wallpaper", |arguments| {
            let Some(path) = arguments.first() else {
                return String::from("usage: wallpaper <path>");
            };

            Palette::write().open(path, 16);

            format!("palette from {path}")
        })
        .window(bar)
        .run();
}
```

```sh
amane ipc call wallpaper ~/Pictures/new.jpg
```

Здесь `~` работает, потому что ваша оболочка (`fish`, `bash`, `zsh`) раскрывает её до того, как `amane` её увидит.

`open` читает изображение сразу, а IPC-обработчики выполняются в потоке отрисовки, поэтому на очень большой картинке оболочка на мгновение замрёт. Если это мешает, пусть скрипт обоев копирует новое изображение поверх одного фиксированного пути, а `open` этого пути вызовите один раз в `main`. `Palette` заметит изменение сам и прочитает файл в фоновом потоке.

## PAM: интерактивная аутентификация

Сервис `Pam` проводит диалог PAM в фоновом потоке. Он показывает каждый запрос и сообщение, чтобы оболочка могла спросить пароль, код подтверждения или другой ответ. Успешная попытка отдельного `Pam` **не** разблокирует сессию. Для интерактивной разблокировки используйте `Lock::authenticate`.

### Запуск аутентификации

Вызывайте `start` из обработчика ввода или другого потока:

```rust
use amane::{Pam, PamConfig};

let result = Pam::start(PamConfig::new("login"));

if let Err(error) = result {
    // показать error
}
```

Имя сервиса выбирает файл политики в `/etc/pam.d`. Выбирайте политику, подходящую вашей оболочке. Пользователь по умолчанию — `$USER`; отдельная аутентификация может выбрать другого:

```rust
Pam::start(PamConfig::new("my-shell").user("alice"));
```

`PamConfig::config_directory(path)` выбирает другой каталог политик. Имя сервиса по-прежнему остаётся именем файла в этом каталоге. Используется `pam_start_confdir` из Linux-PAM; удобно для политик приложений и изолированных тестов.

Одновременно выполняется только одна попытка, включая попытки, запущенные `Lock`. Если другой обработчик ещё активен, `start` возвращает `PamError::Busy`. Новый запуск очищает предыдущие сообщения и результат.

### Запросы и сообщения

Читайте `Pam` в представлении, как любой другой сервис. У каждого `PamMessage` есть `id()`, `text()` и `kind()`:

| Вид | Значение |
|---|---|
| `PamMessageKind::Info` | информация для пользователя |
| `PamMessageKind::Error` | сообщение от модуля PAM для показа |
| `PamMessageKind::Prompt { visible: true }` | запрос, ответ на который можно показывать при вводе |
| `PamMessageKind::Prompt { visible: false }` | запрос, ответ на который нужно скрывать |

`messages()` хранит историю сообщений диалога. `prompt()` возвращает только текущий неотвеченный запрос. На запросы отвечают по одному, даже если модуль прислал несколько сразу.

Сохраните `id` запроса в обработчике ввода. Это не даст запоздалому ответу попасть в следующий запрос или другую попытку:

```rust
use amane::{Pam, PamMessageKind, Service, TextInput};

let pam = Pam::read();
if let Some(prompt) = pam.prompt() {
    let id = prompt.id();
    let mut input = TextInput::new("pam-response")
        .placeholder(prompt.text())
        .focused()
        .on_submit(move |response| {
            if Pam::respond(id, &response).is_ok() {
                TextInput::set_text("pam-response", "");
            }
        });
    if prompt.kind() == (PamMessageKind::Prompt { visible: false }) {
        input = input.password();
    }
    // Добавьте input в дерево виджетов.
}
```

Ответ принимается один раз. Устаревший `id` или повторный ответ даёт `PamError::NoPrompt`. Ответ с нулевым байтом отклоняется, не расходуя запрос. Ответы не попадают в историю сообщений.

Представления только читают сервисы. Вызывайте `start`, `respond` и `abort` из обработчиков, после того как все guard-ы `Pam::read()` или `Lock::read()` отпущены.

### Результаты и отмена

`result()` равно `None`, пока попытка идёт (если её не отменили). Затем там одно из:

| Результат | Значение |
|---|---|
| `PamResult::Success` | и аутентификация, и проверка аккаунта прошли |
| `PamResult::Rejected(error)` | учётные данные или политика аккаунта отклонили попытку |
| `PamResult::Aborted` | попытка отменена |
| `PamResult::Error(error)` | сбой серверной части PAM или обработчика |

`PamError::Native { code, message }` сохраняет код и текст ошибки PAM. Если модуль меняет аутентифицированного пользователя, возвращается `PamError::UserChanged`. Показ сообщения `Error` от модуля сам по себе не означает, что попытка закончилась; итог смотрите в `result()`.

`Pam::abort()` немедленно отменяет попытку и будит ожидающий запрос. Нативный модуль, уже выполняющий работу вне callback-а диалога, должен вернуться, прежде чем его можно будет очистить. `active()` остаётся `true`, пока очистка не завершится, и до этого новый запуск возвращает `Busy`. Поздний результат отменённой попытки отбрасывается.

Для попытки, запущенной блокировкой, `Lock::abort()` также очищает состояние проверки и ошибки блокировки и оставляет сессию заблокированной. Новая блокировка сессии отменяет старую попытку аутентификации.

### Пример

`cargo run --example pam` открывает обычное окно аутентификации. Она использует политику `login` и не блокирует и не разблокирует сессию. Пример использует `App::without_ipc()`, чтобы работать рядом с оболочкой и не занимать её IPC-сокет. Политику и каталог можно выбрать через `AMANE_PAM_SERVICE` и `AMANE_PAM_CONFIG_DIRECTORY`.

Библиотечные тесты компилируют временный модуль PAM и используют временный каталог политик. Они проверяют диалоги, отказ аккаунта, отмену и устаревшие результаты, не проверяя настоящие учётные данные и не меняя системные настройки аутентификации.

> **Уточнение.** `Pam::start` возвращает `Result<(), PamError>`, а не паникует. Если вызывать его из замыкания `App::ipc`, которое обязано вернуть `String`, обработайте ошибку внутри замыкания, как в примере выше, вместо оператора `?`: сигнатура обработчика этого не позволяет без вспомогательной функции.

# Часть VI. Связь с системой

## Команды и файлы

Эта глава про запуск других программ и наблюдение за файлами: клей для всего, что Amane не читает сам.

| Функция | Что делает | Ждёт? |
|---|---|---|
| `amane::spawn(command)` | запускает команду и идёт дальше | нет |
| `amane::output(command)` | выполняет команду и возвращает то, что она напечатала | да, до завершения |
| `amane::lines(command)` | запускает долгоживущую команду и выдаёт каждую её строку | да, для каждой строки |
| `amane::watch_file(path)` | выдаёт элемент при каждом изменении файла | да, для каждого изменения |

Все команды выполняются через `sh -c`, поэтому конвейеры, глоб-маски, `~` и `&&` работают как в терминале.

### Запуск программ

```rust
.on_click(|_| amane::spawn("firefox"));
.on_click(|_| amane::spawn("niri msg action focus-workspace-down"));
.on_click(|_| amane::spawn("notify-send amane 'the bar was clicked'"));
```

`spawn` возвращается сразу, поэтому безопасен в обработчиках ввода. Amane держит отдельный поток, который ждёт завершения процесса, чтобы он не остался зомби.

### Чтение вывода команды

`output` ждёт завершения команды, поэтому никогда не вызывайте его в представлении: это заморозит все окна. Вызывайте его в сервисе, в `new()` или `update()`, которые работают в собственном потоке сервиса:

```rust
use std::time::Duration;

use amane::{App, Full, LayerWindow, Service, Text};

struct Kernel {
    version: String,
}

impl Service for Kernel {
    fn new() -> Self {
        Self { version: amane::output("uname -r") }
    }

    // при работе оболочки больше не меняется
    fn interval() -> Duration {
        Duration::from_secs(3600)
    }
}

fn main() {
    App::new().window(view).run();
}

fn view() -> LayerWindow {
    let kernel = Kernel::read();

    LayerWindow::new().width(Full).height(30.0).child(Text::new(&kernel.version))
}
```

`output` убирает завершающие переводы строк.

> **Исправление.** В книге сказано: «команда, которая завершилась ошибкой или ничего не напечатала, даёт пустую строку». На самом деле `output` (`src/process.rs`) забирает **только stdout**, убирает завершающие `\n` и игнорирует код возврата. Поэтому:
>
> - команда с ненулевым кодом, но непустым stdout вернёт этот stdout;
> - команда, печатающая только в stderr, вернёт `""`;
> - команда, печатающая пустоту, вернёт `""`;
> - паника `failed to run command` возможна, только если не удалось запустить сам `sh`, а не если команда внутри вернула ошибку.

> **Уточнение.** `trim_end_matches('\n')` убирает **все** завершающие переводы строк, а не один. Символы `\r` не удаляются.

### Слежение за выводом команды

Некоторые команды печатают строку при каждом событии: `niri msg event-stream`, `pactl subscribe`, `udevadm monitor`. `lines` выдаёт каждую строку по мере появления, в `listen` сервиса:

```rust
use amane::{App, Full, LayerWindow, Service, Text};

struct Events {
    last: String,
}

impl Service for Events {
    fn new() -> Self {
        Self { last: String::from("waiting") }
    }

    fn listen() {
        for line in amane::lines("niri msg event-stream") {
            Self::write().last = line;
        }
    }
}

fn main() {
    App::new().window(view).run();
}

fn view() -> LayerWindow {
    let events = Events::read();

    LayerWindow::new().width(Full).height(30.0).child(Text::new(&events.last))
}
```

Цикл заканчивается, когда команда завершается. Если цикл прервётся раньше, например из-за паники в `listen`, команда будет убита: `Lines` убивает и дожидается процесса в `Drop`. Так ничего не остаётся висеть.

`lines` читает только stdout. stderr команды наследуется процессом: при запуске через `amane run` он уходит в `/dev/null`.

### Наблюдение за файлом

```rust
use std::fs;

use amane::{App, Full, LayerWindow, Service, Text};

const NOTE: &str = "/tmp/amane-note";

struct Note {
    text: String,
}

impl Service for Note {
    fn new() -> Self {
        Self { text: read_note() }
    }

    fn listen() {
        for _ in amane::watch_file(NOTE) {
            Self::write().text = read_note();
        }
    }
}

fn read_note() -> String {
    fs::read_to_string(NOTE).unwrap_or_default().trim_end().to_string()
}

fn main() {
    App::new().window(view).run();
}

fn view() -> LayerWindow {
    let note = Note::read();

    LayerWindow::new().width(Full).height(30.0).child(Text::new(&note.text))
}
```

`std::fs` — из стандартной библиотеки Rust.

Попробуйте `echo hello > /tmp/amane-note` во время работы бара.

`watch_file` выдаёт элемент при каждой записи, создании или замене файла. Редакторы обычно сохраняют так: пишут новый файл и переименовывают его поверх старого, что завершило бы наблюдение за самим файлом. Поэтому Amane следит за папкой и выбирает изменения вашего файла.

Файл не обязан существовать в момент запуска наблюдения, но его папка — обязана.

> **Исправление.** Оригинал говорит, что `watch_file` даёт элемент «каждый раз, когда файл записан, создан или заменён». Это не весь список: маска наблюдения — `MODIFY | MOVED_TO | CREATE`, поэтому удаление (`DELETE`) и перемещение прочь (`MOVED_FROM`) события не дают. Если файл удалить, итератор просто перестанет получать события. Повторное создание файла с тем же именем снова даст `CREATE`.
>
> Папки с именем файла без родительского каталога (`/tmp/note`) нет в маске: `watch_file` следит именно за родительской папкой, поэтому она должна существовать, иначе будет паника `failed to watch file`.

Чтение файла — на вас, в цикле, как выше. Если файл удалён, `fs::read_to_string` вернёт ошибку, а `unwrap_or_default()` даст пустую строку.

## IPC

IPC позволяет другим программам общаться с вашей работающей оболочкой. Главное применение — горячие клавиши: композитор вызывает `amane ipc call toggle-launcher`, и оболочка открывает лаунчер.

### Переключение окна из командной строки

```rust
use std::time::Duration;

use amane::{App, LayerWindow, Parent, Rectangle, Service};

struct Launcher {
    open: bool,
}

impl Service for Launcher {
    fn new() -> Self {
        Self { open: false }
    }

    fn interval() -> Duration {
        Duration::from_secs(3600)
    }
}

fn main() {
    App::new().ipc("toggle-launcher", toggle).window(view).run();
}

fn view() -> LayerWindow {
    let launcher = Launcher::read();

    LayerWindow::new()
        .width(400.0)
        .height(300.0)
        .visible(launcher.open)
        .child(Rectangle::new().width(Parent).height(Parent).fill("#1e1e2e"))
}

fn toggle(_: &[String]) -> String {
    let mut launcher = Launcher::write();

    launcher.open = !launcher.open;

    if launcher.open {
        String::from("opened")
    } else {
        String::from("closed")
    }
}
```

Из терминала:

```sh
amane ipc call toggle-launcher
```

Команда напечатает `opened`, и лаунчер появится. Запустите ещё раз, чтобы закрыть.

### Как вызов доходит до оболочки

- `App::ipc(name, handler)` регистрирует обработчик под именем. Вызывайте один раз на имя. При повторной регистрации того же имени старый обработчик заменяется.
- Оболочка слушает сокет `$XDG_RUNTIME_DIR/amane.sock`. Если `XDG_RUNTIME_DIR` не задан, оболочка паникует с `failed to find socket: XDG_RUNTIME_DIR is not set`.
- `amane ipc call <name> [arguments...]` подключается к сокету, отправляет имя и аргументы и печатает ответ.
- Обработчик получает аргументы и возвращает `String`. То, что он вернул, печатает `amane ipc call`.
- Обработчик пишет в сервис, поэтому все окна, которые его читают, перерисовываются.

Обработчик выполняется в том же потоке, который рисует, поэтому держите его быстрым. Для медленной работы запустите поток или используйте `amane::spawn`.

> **Уточнение.** Регистрация обработчика принимает `fn(&[String]) -> String`. Замыкание без захвата подойдёт (Rust приведёт его к указателю на функцию), а замыкание, которое захватывает переменные, — нет. Состояние держите в сервисе.

### Передача аргументов

Всё после имени передаётся обработчику как список строк:

```rust
fn main() {
    App::new().ipc("say", say).window(view).run();
}

fn say(arguments: &[String]) -> String {
    let words = arguments.join(" ");

    Message::write().text = words.clone();

    format!("showing: {words}")
}
```

```sh
amane ipc call say hello world
```

Обработчик получит `["hello", "world"]`. Аргументы не могут содержать переводы строк: они передаются по одному на строку, и перевод строки превратится в границу аргумента.

Вызов имени без обработчика отвечает `no handler named <name>`.

### Привязка вызовов к клавишам

niri:

```kdl
binds {
    Mod+Space { spawn "amane" "ipc" "call" "toggle-launcher"; }
}
```

Hyprland:

```text

```

Sway:

```text

```

### Одна оболочка за раз

Сокет один на сессию, поэтому одновременно слушать вызовы может только одно приложение Amane. Второй слушатель сразу останавливается с `failed to listen: amane is already running`. `amane run` проверяет заранее и сообщает об этом в терминале, а `amane restart` останавливает работающую оболочку перед запуском новой.

`amane dev` перезапускает собственную оболочку, не натыкаясь на это, но не может остановить оболочку, запущенную другим способом. Остановите повседневную оболочку (запущенную `amane run`) перед `amane dev`.

Для отдельного окна, которому IPC не нужен, используйте `App::new().without_ipc()`. Оно может работать рядом с оболочкой и не занимает её сокет. IPC включён по умолчанию; `without_ipc()` отключает слушателя, даже если обработчики зарегистрированы.

Если `amane ipc call` говорит `amane is not running`, в этой сессии оболочка не слушает IPC.

## D-Bus

D-Bus — способ, которым общаются большинство системных служб Linux: NetworkManager, UPower, BlueZ, logind, медиаплееры, серверы уведомлений. Встроенные сервисы Amane используют его, а вы можете применять ту же обёртку для всего, что они не покрывают.

### Две шины

```rust
let bus = Bus::system();    // общая для всех пользователей: NetworkManager, UPower, logind, BlueZ
let bus = Bus::session();   // ваши программы: медиаплееры, уведомления, трей
```

На всю оболочку приходится по одному соединению на шину, общему для всех потоков. Если шина недоступна, каждый вызов на ней отвечает «ничего» вместо ошибки. Шина пробуется только один раз, поэтому шина, запустившаяся после вашей оболочки, потребует перезапуска оболочки.

> **Уточнение.** Соединение создаётся лениво, при первом обращении к `Bus::system()` или `Bus::session()`, а не при запуске приложения. Результат кэшируется на всё время работы процесса. Если в момент первого обращения шина была недоступна, более поздние попытки не делаются.

### Чтение свойства

```rust
use std::time::Duration;

use amane::{App, Bus, Full, LayerWindow, Service, Text};

struct Wifi {
    enabled: bool,
}

impl Service for Wifi {
    fn new() -> Self {
        Self { enabled: read_enabled() }
    }

    fn interval() -> Duration {
        Duration::from_secs(5)
    }

    fn update(&mut self) -> bool {
        let enabled = read_enabled();

        let changed = enabled != self.enabled;

        self.enabled = enabled;

        changed
    }
}

fn read_enabled() -> bool {
    let bus = Bus::system();

    let enabled = bus.property(
        "org.freedesktop.NetworkManager",    // кого спрашивать
        "/org/freedesktop/NetworkManager",   // какой объект
        "org.freedesktop.NetworkManager",    // какой интерфейс
        "WirelessEnabled",                   // какое свойство
    );

    enabled.bool()
}

fn main() {
    App::new().window(view).run();
}

fn view() -> LayerWindow {
    let wifi = Wifi::read();

    let label = if wifi.enabled { "wifi on" } else { "wifi off" };

    LayerWindow::new().width(Full).height(30.0).child(Text::new(label))
}
```

Чтобы найти имена, исследуйте шину инструментом `busctl`, `qdbusviewer` или D-Spy.

Вызовы D-Bus ждут ответа, поэтому делайте их в потоке сервиса, а не в представлении.

### Значения

Любой ответ — это `Value`:

| Вариант | Как читать |
|---|---|
| `Value::Bool` | `.bool()` |
| `Value::Number` | `.number()` как `f64`, независимо от числового типа D-Bus |
| `Value::Text` | `.text()` |
| `Value::List` | `.list()` |
| `Value::Map` | `.get("key")` |
| `Value::Nothing` | вызов не удался или ответа не было |

Каждый геттер даёт пустой результат для неподходящего типа: `false`, `0.0`, `""`, пустой список или `Value::Nothing`. Поэтому вызов к незапущенной программе даёт `Value::Nothing`, и чтение показывает пустоту вместо падения. Геттеры можно объединять в цепочку:

```rust
let title = metadata.get("xesam:title").text();
let first_artist = metadata.get("xesam:artist").list().first().map(|artist| artist.text());
```

### Вызов методов

```rust
let answer = bus.call(destination, path, interface, method, &arguments![...]);
```

`arguments!` превращает обычные значения Rust в аргументы D-Bus: `bool`, `i32`, `u32`, `i64`, `f64`, `&str`, `String` и `Vec<String>`. Для других типов D-Bus создайте `Argument` напрямую, например `Argument::Path(String::from("/org/..."))` для объектного пути или `Argument::Variant(...)`.

Поставьте Spotify на паузу через MPRIS:

```rust
let bus = Bus::session();

bus.call(
    "org.mpris.MediaPlayer2.spotify",
    "/org/mpris/MediaPlayer2",
    "org.mpris.MediaPlayer2.Player",
    "Pause",
    &[],
);
```

Большинство методов отвечают одним значением, и оно возвращается само. Метод, отвечающий несколькими значениями, даёт `Value::List`.

Чтобы задать свойство:

```rust
bus.set_property(destination, path, interface, "Powered", Argument::from(true));
```

> **Уточнение.** `set_property` ничего не возвращает: результат операции, включая ошибку, вы не увидите. Если нужно знать, применилось ли свойство, прочитайте его обратно или вызывайте метод интерфейса напрямую через `call`.

### Прослушивание сигналов

Программы объявляют изменения сигналами. `signals` ждёт каждый из них, поэтому вызывайте его в `listen` сервиса:

```rust
fn listen() {
    let bus = Bus::system();

    for signal in bus.signals("org.freedesktop.DBus.Properties", "PropertiesChanged") {
        if signal.path() != "/org/freedesktop/NetworkManager" {
            continue;
        }

        let enabled = read_enabled();

        Self::write().enabled = enabled;
    }
}
```

У каждого `Signal` есть `sender()`, `path()` и `arguments()`. `sender()` — уникальное имя отправителя, например `:1.42`, а не известное имя вроде `org.mpris.MediaPlayer2.mpv`.

> **Уточнение.** `signals(interface, name)` фильтрует только по интерфейсу и имени сигнала. Отправителя и путь нужно проверять вручную через `signal.sender()` и `signal.path()`, как в примере. Неверное имя интерфейса или сигнала паникует при создании подписки.

### Ответы на вызовы

Ваша оболочка может предоставить собственный интерфейс D-Bus, чтобы другие программы могли её вызывать:

```rust
use amane::{App, Bus, LayerWindow, Service, Text, arguments};

struct Server;

impl Service for Server {
    fn new() -> Self {
        Server
    }

    fn listen() {
        let bus = Bus::session();

        // сначала подписка, затем захват имени, чтобы не пропустить первые вызовы
        let methods = bus.methods("/org/example/Shell", "org.example.Shell");

        if !bus.own("org.example.Shell") {
            return;
        }

        for method in methods {
            if method.name() == "Ping" {
                method.reply(&arguments!["pong"]);
            }
        }
    }
}

fn main() {
    App::new().window(view).run();
}

fn view() -> LayerWindow {
    // одно чтение сервиса запускает его поток
    let _server = Server::read();

    LayerWindow::new().width(200.0).height(30.0).child(Text::new("serving"))
}
```

Проверьте:

```sh
busctl --user call org.example.Shell /org/example/Shell org.example.Shell Ping
```

- `own(name)` занимает известное имя и возвращает `false`, если им уже владеет другая программа. Amane никогда не отбирает имя.
- `methods(path, interface)` ждёт каждый вызов к этому объекту и интерфейсу.
- `method.arguments()` даёт аргументы вызова, `method.reply(...)` отвечает на него.
- `bus.emit(path, interface, name, &arguments![...])` отправляет ваш собственный сигнал.

> **Уточнение.** `own` использует флаг `DoNotQueue`: имя не ставится в очередь. Если другая программа освободит его позже, Amane не получит его автоматически — потребуется перезапуск оболочки. `own` возвращает `true` и при `AlreadyOwner`, то есть повторный вызов безопасен.

> **Уточнение.** `methods` фильтрует по точному пути и интерфейсу; метод с другим путём или интерфейсом не придёт. Если вызывающий уходит до ответа, `reply` молча ничего не делает.

## Как работает команда `amane`

В главе «Начало работы» описаны команды. Здесь — то, что полезно знать при отладке.

### Пути

| Что | Путь |
|---|---|
| Конфигурация по умолчанию | `~/.config/amane` или `$XDG_CONFIG_HOME/amane` |
| Сохранённая цель | `~/.local/state/amane/config-path` или `$XDG_STATE_HOME/amane/config-path` |
| Кэш | `~/.cache/amane` или `$XDG_CACHE_HOME/amane` |
| Распакованная библиотека | `~/.cache/amane/library/` |
| Сгенерированный проект | `~/.cache/amane/project/` |
| Результаты сборки | `~/.cache/amane/project/target/` |
| Скомпилированная оболочка | `~/.cache/amane/amane-shell` |
| IPC-сокет | `$XDG_RUNTIME_DIR/amane.sock` |

`AMANE_CONFIG` переопределяет папку конфигурации для всех команд, не трогая сохранённую цель.

### Что именно делают команды

- **`amane compile`** запускает `cargo build` без `--release`. Оптимизированы только зависимости; пользовательский код собирается в debug-профиле. Готовый бинарник копируется рядом (`amane-shell.new`) и переименовывается поверх `amane-shell`, потому что запись поверх запущенного файла невозможна.
- **`amane dev`** следит за папкой `src/` опросом каждые 500 миллисекунд (снимок времени изменения всех файлов, рекурсивно). При сохранении пересобирает проект, убивает свой старый процесс и запускает новый. Если сборка не удалась, старый процесс остаётся работать.
- **`amane run`** запускает `~/.cache/amane/amane-shell` в отдельной группе процессов, перенаправляя stdin, stdout и stderr в `/dev/null`. Поэтому вывод оболочки и `AMANE_FRAMES` при `amane run` не виден. Запускайте `~/.cache/amane/amane-shell` напрямую, если нужна отладка.
- **`amane restart`** останавливает процесс только с точным полным путём `~/.cache/amane/amane-shell` (через `pkill -xf`), ждёт освобождения IPC-сокета до 3 секунд и запускает сохранённую оболочку. Оболочку из `amane dev` он не трогает.
- **`amane clean`** удаляет только `~/.cache/amane/project/`. `library/` и `amane-shell` остаются, поэтому `amane run` продолжает работать.

> **Исправление.** Справка CLI называет результат `amane compile` «optimised shell», но это не release-сборка. На поведение это не влияет, однако не стоит ожидать release-производительности от собственного кода оболочки.

## Поиск неисправностей

### Оболочка не запускается

| Сообщение | Причина | Что делать |
|---|---|---|
| `failed to bind wlr-layer-shell` | композитор не поддерживает слойные окна | используйте композитор с поддержкой: niri, Hyprland, Sway, river |
| `failed to listen: amane is already running` | в этой сессии уже работает другая оболочка Amane | остановите её, см. главу об IPC |
| `failed to run: no window set` | у `App` нет ни одного окна | добавьте хотя бы `.window`, `.window_per_monitor`, `.normal_window` или `.lock` |
| `failed to read shader` | неверный путь к шейдеру | используйте абсолютный путь, см. главу о шейдерах |
| `failed to find socket: XDG_RUNTIME_DIR is not set` | переменная не задана | запускайте из Wayland-сессии, где `XDG_RUNTIME_DIR` выставлен |
| `failed to start watching files` | не удалось создать inotify | проверьте лимиты inotify или права |

### Окно выглядит неправильно

| Проблема | Решение |
|---|---|
| Обычные окна перекрывают бар | добавьте бару `.space(Zone::Reserve)` |
| Бар перекрывает полноэкранное видео | добавьте `.layer(Layer::Top)`. По умолчанию `Overlay`, который выше всего. |
| Окно в середине экрана | добавьте `anchor_vertical` или `anchor_horizontal`. Оба по умолчанию `Middle`. |
| Цвет показывается ярко-розовым | hex-строка написана с ошибкой. Amane показывает розовый вместо падения. |
| Изображение не показывается | путь должен быть абсолютным, а формат — PNG, JPEG или SVG |
| Текст выходит за границы | добавьте `.elide()` или `.wrap()` |
| Методов вроде `.stroke` нет | добавьте `Shape` в строку `use` |

### Ввод не работает

| Проблема | Решение |
|---|---|
| Печать ничего не делает | дайте окну `.keyboard(Keyboard::OnDemand)` или `Keyboard::Exclusive` |
| `on_key` никогда не вызывается | то же самое. Клавиши приходят только окну с фокусом клавиатуры. |
| Клики проходят сквозь окно | проверьте `.click_through()` и `.input_region(...)`, не исключающие нужную часть |
| Клики не проходят через пустую часть окна | задайте `.input_region(...)` или скройте окно `.visible(false)`, пока оно пусто |

### Оболочка зависает

- **Представление вызывает `write()`.** Представление может ещё держать `read()` того же сервиса, и запись будет ждать вечно. В представлениях только читайте.
- **Представление чего-то ждёт.** `amane::output`, чтение файлов, вызовы D-Bus и `sleep` блокируют поток, который рисует все окна. Перенесите их в сервис.

### Оболочка потребляет много CPU

Запустите её с `AMANE_FRAMES=1`, чтобы печатать строку на каждый кадр:

```sh
AMANE_FRAMES=1 ~/.cache/amane/amane-shell
```

Любое значение переменной включает вывод; именно `1` не обязательно. Каждая строка показывает, какое окно рисовалось, время с его прошлого кадра и сколько заняли представление, отрисовка и GPU. Также печатается, какой сервис разбудил окна. Ищите:

- **Кадры, которые не прекращаются.** Что-то постоянно просит кадры: представление, всегда вызывающее `request_frame()`, или шейдер, в исходнике которого есть слово `time`.
- **Сервис, будящий окна при каждом опросе.** Его `update()` возвращает `true`, хотя ничего не изменилось. Сравнивайте старое и новое значение и возвращайте результат сравнения.
- **Медленное представление.** В представлении выполняется реальная работа. Перенесите её в сервис.

### Оболочка потребляет много памяти

Полноэкранным окнам и маскам нужны буферы GPU, которые на встроенной графике могут занимать системную память. Amane просит графический backend экономить память, но потребление всё равно растёт с размером и числом окон. Некоторые backend-ы эту просьбу игнорируют.

Повёрнутые или растянутые маски и маски не шире и не выше одного физического пикселя могут требовать больше памяти, чем обычные скруглённые маски.

При профилировании смотрите и память процесса, и память GPU. Общие буферы могут попадать в оба счётчика, поэтому их сумма может завышать реальное потребление.

### Экран блокировки не разблокируется

См. раздел «Безопасное тестирование» в главе об экране блокировки, чтобы вернуться в заблокированную сессию.

# Приложение. Исправления и уточнения

Ниже перечислены расхождения между опубликованной книгой Amane и исходным кодом версии **0.1.2**. Ссылки на файлы даны относительно корня репозитория `MystiaFin/amane`. Этот же список лежит отдельно в [CORRECTIONS.md](CORRECTIONS.md).

## 1. `Window::resizable` по умолчанию `true`

**Где в книге:** шпаргалка и глава «Multiple Windows and Monitors» говорят, что окно по умолчанию не изменяется в размере.

**На самом деле:** в `src/window.rs` конструктор `Window::new()` ставит `resizable: true`. Пользователь может менять размер обычного окна, пока не вызван `.resizable(false)`.

```rust
let window = Window::new()
    .title("Настройки")
    .size(640.0, 480.0)
    .resizable(false);
```

## 2. Парольный `TextInput` очищается после Enter

**Где в книге:** «Enter не очищает поле само по себе; вызывайте `set_text`».

**На самом деле:** в `src/widgets/text_input/targets.rs` функция `submit` сначала вызывает `on_submit` с настоящим текстом, а затем, если поле парольное, делает `TextInput::set_text(id, "")`. Очистка происходит **только если задан `on_submit`**:

```rust
TextInput::new("password")
    .password()
    .on_submit(|password| {
        // password — настоящий текст, а не •••
        // после возврата из этого обработчика поле станет пустым
    });
```

Если `on_submit` нет, Enter не делает ничего. Если вызвать `set_text` внутри `on_submit` у парольного поля, автоматическая очистка всё равно перезапишет текст пустой строкой.

Символ скрытия — `•` (U+2022), по одному на каждый символ, а не точка `.`.

## 3. `Palette` до загрузки изображения

**Где в книге:** «до открытия изображения `Palette` хранит набор цветов по умолчанию».

**На самом деле:** `Palette::colors()` возвращает пустой срез. Цвета по умолчанию есть только у отдельных геттеров (`src/services/palette.rs`):

| Метод | Значение без изображения |
|---|---|
| `colors()` | пустой список |
| `dominant()` | `#11111b` |
| `background()` | `#11111b` |
| `accent()` | `#89b4fa` |
| `foreground()` | вычисляется как читаемый цвет на `background()` |
| `on_accent()` | чёрный или белый, в зависимости от `accent()` |
| `light()` | `false` |

Поэтому `palette.colors()[0]` до `open()` паникует. Проверяйте `colors().is_empty()` или используйте `dominant()`/`background()`.

## 4. `output`: stdout, stderr и код возврата

**Где в книге:** «команда, которая завершилась ошибкой или ничего не напечатала, даёт пустую строку».

**На самом деле:** `amane::output` (`src/process.rs`) запускает `sh -c`, забирает **только stdout**, обрезает завершающий `\n` и игнорирует код возврата. `stderr` не попадает в результат.

Следствия:

- команда с ненулевым кодом, но непустым stdout вернёт этот stdout;
- команда, которая печатает только в stderr, вернёт `""`;
- паника `failed to run command` возможна только если не удалось запустить сам `sh`, а не если команда внутри вернула ошибку.

`lines()` также читает только stdout; stderr наследуется процессом (при `amane run` он направлен в `/dev/null`).

## 5. `watch_file` не сообщает об удалении

**Где в книге:** «даёт элемент каждый раз, когда файл записан, создан или заменён».

**На самом деле:** `src/files.rs` следит за **родительской папкой** с маской `MODIFY | MOVED_TO | CREATE`. Удаление (`DELETE`) и перемещение прочь (`MOVED_FROM`) не обрабатываются. Если файл удалить, итератор просто перестанет получать события. Повторное создание файла с тем же именем снова даст событие `CREATE`.

Папка должна существовать: иначе `watch_file` паникует с `failed to watch file`.

## 6. Неполный список зависимостей

**Где в книге:** перечислены Wayland, `libxkbcommon`, fontconfig, Vulkan loader, PulseAudio и PAM.

**На самом деле:** для сборки также нужны:

- C-компилятор (`gcc`/`build-essential`);
- `pkg-config`;
- заголовки и библиотеки **FreeType**;
- заголовки и библиотеки **expat**.

Полный список из `install.sh`:

| Дистрибутив | Пакеты |

| Debian/Ubuntu | `build-essential pkg-config libwayland-dev libxkbcommon-dev libfontconfig-dev libfreetype-dev libexpat1-dev libvulkan1 libpulse-dev libpam0g-dev` |
| Fedora | `gcc pkgconf-pkg-config wayland-devel libxkbcommon-devel fontconfig-devel freetype-devel expat-devel vulkan-loader pulseaudio-libs-devel pam-devel` |

## 7. `amane new` и `AMANE_CONFIG`

**Где в книге:** «`amane new` спрашивает, куда положить оболочку».

**На самом деле:** без папки в аргументах команда сначала смотрит на переменную окружения **`AMANE_CONFIG`**. Если она задана, вопрос не задаётся, и оболочка создаётся по этому пути (`cli/src/new.rs`, `cli/src/paths.rs`). Это недокументированный способ переопределить папку конфигурации; он же используется командой `amane target` без аргументов для печати пути.

Сохранённый путь от `amane target` **не** используется как место для `amane new` без аргументов: в этом случае всё равно задаётся вопрос (если `AMANE_CONFIG` не установлена). После успешного `amane new <folder>` путь запоминается, если это не папка по умолчанию.

## 8. Устаревшая команда `amane startup`

**Где в книге:** команда не упомянута.

**На самом деле:** `amane startup [--example]` — старый псевдоним `amane new`. Она работает, печатает предупреждение о будущем удалении и принимает те же аргументы, но без папки (то есть `amane startup /path` не поддерживается).

## 9. `Gradient::radial` доходит до углов

**Где в книге:** «радиальный градиент до краёв прямоугольника».

**На самом деле:** радиус радиального градиента вычисляется до **углов** прямоугольника, поэтому у углов цвет уже соответствует конечной остановке, а у середины сторон — ещё нет. Это заметно на вытянутых прямоугольниках. Источник: `src/graphics/gpu/gradient.rs`.

## 10. `.focused()` у `TextInput` забирает фокус каждый кадр

**Где в книге:** «поле получает клавиатуру, как только нарисовано».

**На самом деле:** `collect_targets` при каждом кадре вызывает `focus::set(id, ...)`, если у поля стоит `.focused()`. Поэтому:

- `.focused()` имеет смысл только у одного поля;
- если нарисовать два таких поля, фокус будет у последнего;
- такое поле может «отобрать» фокус у поля, выбранного кликом, при следующей перерисовке.

Для поля, которое должно получать фокус только после клика, `.focused()` не нужен.

## 11. `TextInput::set_text` и `on_change`

`set_text` заменяет текст и ставит курсор в конец, но **не вызывает** `on_change`. `on_change` срабатывает только на изменения, сделанные клавишами. Это стоит учитывать, если вы синхронизируете поле с сервисом.

## 12. `Image::loaded` проверяет не тот вариант изображения

**Где в книге:** «`Image::loaded(path)` сообщает, готово ли изображение, и запускает загрузку, если её ещё никто не просил».

**На самом деле:** `Image::loaded(path)` проверяет и запускает вариант **полного размера, без размытия и без thumbnail** (`src/style/image.rs`). Если вы рисуете `Image::cover(path).thumbnail(64, 64).blurred(8)`, `loaded(path)` может вернуть `true`, хотя нужный уменьшенный/размытый вариант ещё декодируется, или наоборот.

Кэш изображений в `src/graphics/image.rs` ключуется парой «путь + размер thumbnail + радиус размытия». Поэтому:

- один и тот же файл в разных вариантах декодируется и хранится отдельно;
- изменение файла по тому же пути не обновляет уже закэшированную картинку — нужен новый путь;
- полноразмерные изображения освобождаются, когда их больше не рисует ни одно окно, а уменьшенные копии остаются в кэше.

## 13. Разметка в уведомлениях не отображается как разметка

**Где в книге:** «тело уведомления может содержать простую разметку вроде `<b>`».

**На самом деле:** это верно для протокола `org.freedesktop.Notifications`, но `Text` в Amane не разбирает HTML и не поддерживает rich text. Теги `<b>`, `<i>`, `<a href=...>` будут нарисованы буквально. Если нужен чистый текст, уберите теги самостоятельно (и не пытайтесь интерпретировать HTML как доверенный).

## 14. Специальные рабочие столы Hyprland и теги Mango

**Где в книге:** сказано, что `Workspaces` поддерживает Hyprland и Mango, но не описаны ограничения.

**На самом деле:**

- Hyprland: специальные рабочие столы (special workspaces, scratchpad) пропускаются и в список не попадают (`src/compositor/hyprland.rs`).
- Mango: теги нумеруются с 1 до 31, имена тегов через IPC не передаются, поэтому `Workspace::name()` всегда `None`; на одном мониторе может быть активно несколько тегов (`src/compositor/mango.rs`).
- Mango определяется по `MANGO_INSTANCE_SIGNATURE` и использует собственный IPC-сокет; `mmsg` не требуется.

## 15. `Brightness` опрашивается каждые 500 мс

**Где в книге:** интервал не указан.

**На самом деле:** `src/services/brightness.rs` задаёт `Duration::from_millis(500)`. Остальные интервалы: `Battery` — 5 с, `Cpu` — 2 с, `Memory` — 2 с, `Network` — 1 с, `Bluetooth` — 2 с, `Media` — 1 с, `Apps` — 30 с, `Palette` — 500 мс.

## 16. `App::ipc` принимает указатель на функцию

**Где в книге:** не сказано, что замыкания с захватом не подходят.

**На самом деле:** сигнатуры `App::window`, `App::window_per_monitor`, `App::normal_window`, `App::lock`, `App::ipc` и `open_window` принимают `fn`, а не `impl Fn`. Замыкание, которое захватывает переменные, не скомпилируется:

```rust
// не скомпилируется: захватывает prefix
let prefix = "toggle";
App::new().ipc(prefix, handler);
```

Используйте обычную функцию или `fn`-указатель без захвата. Состояние храните в сервисе.

## 17. `Battery::full()` — это статус, а не только «заряжен и подключён»

`full()` возвращает `true`, если ядро сообщает статус `Full` **или** `Not charging`. Обычно это значит «подключён и не заряжается», но при порогах зарядки и особенностях драйвера возможны нюансы. Если нужно точно знать, подключено ли питание, отдельного метода в `Battery` нет — читайте `/sys/class/power_supply` самостоятельно.

## 18. `Text` и числовой вес шрифта

Вес задаётся `Weight` или числом `u16` (например, `.weight(600)`). Число округляется до ближайшей сотни и отображается на именованный вес; значения выше 900 дают `Black`, ниже 50 — `Thin`. Это не произвольная вариативная ось шрифта, а выбор одного из девяти именованных начертаний.

## 19. `amane run` прячет вывод

`amane run` запускает скомпилированную оболочку в отдельной группе процессов и перенаправляет stdin/stdout/stderr в `/dev/null`. Поэтому сообщения об ошибках и отладочный вывод `AMANE_FRAMES` при обычном `amane run` не видны. Для отладки запускайте `~/.cache/amane/amane-shell` напрямую.

`amane restart` останавливает только процесс с точным путём `~/.cache/amane/amane-shell`, поэтому не трогает оболочку, запущенную через `amane dev` из `~/.cache/amane/project/target/debug/amane-shell`.

## 20. `amane clean` не удаляет скомпилированную оболочку

Команда удаляет только `~/.cache/amane/project/`. Файл `~/.cache/amane/amane-shell` и распакованная библиотека остаются, поэтому `amane run` продолжает работать. Следующие `compile` или `dev` собирают проект заново с нуля.

## 21. `Notifications` и `running()`

`Notifications::running()` возвращает `false`, если D-Bus-имя `org.freedesktop.Notifications` уже занято другим демоном. В этом случае Amane не получает уведомления, но сервис продолжает существовать. Чтение `Notifications` в представлении, которое открыто при старте, важно: именно первый `read()` запускает фоновый `listen` и попытку занять имя.

## 22. `Service::read()` и `Service::write()` — это блокировки

`read()` возвращает `RwLockReadGuard`, а `write()` — `RwLockWriteGuard` (обёртку `Write`). Их нельзя удерживать через вызов, который сам читает тот же сервис, и нельзя вызывать `write()` во время отрисовки представления: это приведёт к дедлоку. Запись в обработчике ввода или в фоновом потоке — нормальный вариант.

## 23. Паника в `listen` перезапускает сервис

Если `listen` паникует, Amane печатает `amane: <тип> stopped, starting it again` и перезапускает его через 5 секунд. Если `listen` завершается **нормально**, сервис остаётся с последним значением и больше не обновляется; это не ошибка, а штатное завершение.

## 24. `Lock::start` без `App::lock`

Если в `App` не задан `.lock(...)`, вызов `Lock::start()` печатает `amane: Lock::start needs a lock screen, see App::lock` и не блокирует сессию. Экран блокировки также требует поддержки `ext-session-lock` со стороны композитора.

## 25. `watch_file` и `output` — не универсальные инструменты

- `watch_file` не является рекурсивным наблюдателем: он смотрит только за одной папкой и одним именем файла.
- `output` не возвращает код возврата и stderr; для сложной логики используйте `lines` или собственный процесс.
- `lines` убивает дочерний процесс при уничтожении итератора (в том числе при выходе из цикла `for`), что важно для долгоживущих команд.

## 26. Опечатка в справке `amane`

Справка CLI называет результат `amane compile` «optimised shell», но фактически `cli/src/cargo.rs` запускает `cargo build` без `--release`. Это debug-сборка с оптимизированными зависимостями; код пользователя остаётся неоптимизированным. На поведение это не влияет, но не стоит ожидать release-производительности.
